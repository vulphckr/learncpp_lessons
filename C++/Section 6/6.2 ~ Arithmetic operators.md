#### Operatori aritmetici unari
Esistono **due operatori aritmetici *unari***: `operator+` (***unary plus***) e `operator-` (***unary minus***).
	Si ricorda che un operatore è *unario* se hanno **un solo operando**.

`operator-`, una volta *computato*, **restituisce il valore dell'operando moltiplicato per `-1`**. In particolare, Se `x = 5`, `-x` è `-5`.

`operator+`, una volta *computato*, **restituisce il valore dell'operando**. In altre parole, se `x = 5`, `+x` vale `5`. L'uso di questo operatore è *ridondante*, ed è stato aggiunto unicamente per la simmetricità con `operator-`.

Questi operatori vanno posti, se utilizzati. ***subito prima dell'operando***; si scrive quindi `-5` e non `- 5`, in quanto potrebbe causare problematiche con `operator-` binario (***binary subtraction***).

#### Operatori aritmetici binari
Ci sono ***cinque*** operatori aritmetici binari:
- `operator+` - ***binary addition***;
- `operator-` - ***binary subtraction***;
- `operator*` - ***binary multiplication***;
- `operator/` - ***binary division***;
- `operator%` - ***binary remainder***.

Gli operatori di **addizione, sottrazione e moltiplicazione** ***funzionano esattamente come funzionano in matematica***.

Tuttavia, gli operatori di **divisione e resto** hanno la necessità di alcuni chiarimenti in merito al loro funzionamento.

#### Divisioni tra *integers* e *floating point*
L'operatore di ***divisione*** ha due "modalità": **divisione intera e divisione frazionaria**.

Se ***almeno un operando è di tipo floating point*** si avrà ***divisione frazionaria*** (*floating point division*). In questo caso, il risultato è un *valore floating point* ottenuto dalla divisione dei due operandi, mantenendo anche la parte frazionaria. Essendo usati valori *floating point* possono verificarsi [[4.8 ~ Floating point numbers#*Rounding errors* make floating point comparisons tricky|errori di arrotondamento]].

Se ***entrambi gli operandi sono integers*** si avrà ***divisione intera***. In questo caso, il risultato è un *integer* ottenuto dalla divisione dei due operandi, in cui **la parte frazionaria verrà rimossa**. Per esempio, `7 / 4 = 1` - matematicamente il risultato sarebbe `1.75`  ma essendo la divisione *intera* la parte frazionaria viene rimossa e quindi il risultato è `1`.

#### Usare `static_cast<>` per forzare divisioni frazionarie
Supponiamo di voler effettuare una divisione intera, **mantenendo la parte frazionaria nel risultato**. Come potremmo fare?

Abbiamo visto, [[4.12 ~ Introduction to type conversion and static_cast|in una precedente lezione]], come possiamo usare l'operatore `static_cast<>` per effettuare ***conversioni di tipi di dato***, per esempio per stampare il valore ASCII corrispondente a un `char`, è possibile convertire questo `char` in un `int` tramite `static_cast<>` e poi stampare il valore.

Anche in questo caso `static_cast<>` si dimostra utile: è possibile ***forzare una divisione frazionaria*** *a partire da una divisione intera* semplicemente **convertendo uno dei due operandi *integer* ad un tipo *floating point*** tramite `static_cast`.

```cpp
#include <iostream>

int main() {
	constexpr int x { 7 };
	constexpr int y { 4 };
	
	// La divisione è, di base, intera
	std::cout << "(Intera) 7 / 4 = " 
		<< x / y << '\n'; 
	
	// La divisione diventa frazionaria	
	std::cout << "(Frazionaria) 7 / 4 = " 
		<< static_cast<double>(x) / y << '\n'; 
	
	return 0;
}
```
Output:
```
1
1.75
```

#### Divisione per `0` e `0.0` 
Eseguire divisioni per `0` darà comportamenti imprevisti qui nello stesso modo in cui accade in matematica.

***Divisioni intere*** aventi `0` come divisore causeranno ***un crash del programma***.
```cpp
#include <iostream>

int main() {
	constexpr dividendo { 14 };
	constexpr zero { 0 };
	
	// Il programma crasha!
	std::cout << dividendo / zero << '\n';
	return 0;
}
```

***Divisioni frazionarie*** aventi `0` o `0.0` come divisore hanno risultato ***implementation-defined***, ossia che dipende da *compilatore o architettura*; tale risultato o è conforme allo standard IEEE754 per i numeri a virgola mobile (quindi risulterà `NaN` o `Inf`, valori visti [[4.8 ~ Floating point numbers#`nan` e `inf`|qui]]), oppure [[1.6 ~ Uninitialized variables and undefined behavior|undefined behavior]].

#### Operatori aritmetici di assegnazione
Ci sono ***cinque*** operatori aritmetici di ***assegnazione***:
- `operator+=` - ***addition assignment***;
- `operator-=` - ***subtraction assignment***;
- `operator*=` - ***multiplication assignment***;
- `operator/=` - ***division assignment***;
- `operator%=` - ***remainder assignment***.

Fino ad ora, se avevamo bisogno di **aggiungere un valore al valore di una variabile già definita** dovevamo scrivere
```cpp
x = x + 4; // aggiungi 4 al valore di x
```
Questo codice è diretto e funzionante, ma **siccome è molto frequente l'uso di questa sintassi** sono stati introdotti gli ***operatori di assegnazione aritmetica***, che permettono di eseguire **assegnazioni** sulla base **del risultato di una certa operazione matematica**. 

Al posto di scrivere `x = x + 4` possiamo scrivere `x += 4` ed ottenere lo stesso risultato - ogni [[6.2 ~ Arithmetic operators#Operatori aritmetici binari|operatore aritmetico binario]] possiede il proprio corrispondente operatore di assegnazione.

#### Operatori *modificanti* e *non-modificanti*
Un operatore si dice ***modificante*** se **può modificare il valore di uno dei suoi operandi**. 

In C++, la maggior parte degli operatori sono ***non modificanti***, ossia che *usano gli operandi senza modificarli* e servono solo a calcolare un valore. Tuttavia ci sono ***due grandi classi*** di operatori che ***modificano il valore del loro operando di sinistra***:
- ***Operatori di assegnazione***: sia [[6.2 ~ Arithmetic operators#Operatori aritmetici di assegnazione|aritmetici]] che *bitwise*;
- ***Operatori di incremento***: `operator++` e `operator--`.
