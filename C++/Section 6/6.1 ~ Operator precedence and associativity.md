Questo capitolo riprenderà ciò che è stato detto nella lezione [[1.9 ~ Introduction to literals and operators|1.9]], in particolare la parte relativa agli ***operatori***.

Riprendendone la definizione, un'**operazione** è un *processo matematico* che, a partire **da zero o più valori in input**, chiamati ***operandi***, producono **un nuovo valore**, chiamato ***risultato*** o *valore di output*. L'operazione che viene effettuata viene *denotata* da un simbolo chiamato ***operatore***.

Per esempio, l'operazione `2 + 3` è una operazione di *somma*, in cui `2` e `3` sono **gli operandi**, `+` è **l'operatore** di *somma*, mentre `5` è il **risultato**.

#### Valutazione di *espressioni composte*
Parliamo ora di ***espressioni composte***, ossia di *espressioni* in cui **sono presenti più operazioni da eseguire**. Un esempio di espressione composta è `4 + 2 * 3`.

Problema principale delle espressioni composte è ***l'ordine in cui le operazioni in esse contenute devono essere valutate***; per esempio, l'espressione appena vista, deve essere valutata come `(4 + 2) * 3`, che fa `18`, oppure `4 + (2 * 3)`, che fa `10`?

Come può il compilatore capire l'ordine di valutazione? Devono essere fatte due cose:
- A ***compile-time*** il compilatore *deve analizzare l'espressione* e **determinare come gli operandi devono essere raggruppati con i relativi operatori**. Per capire questo, sono necessarie ***regole di precedenza e associatività degli operatori***, che introdurremo a breve.
- A ***compile-time o runtime*** (sulla base di quando l'operazione deve essere valutata effettivamente), **gli operandi vengono valutati** e si produce il risultato dell'espressione.

#### Precedenza degli operatori
**Ogni operatore possiede un *livello di precedenza***. Tale livello di precedenza viene usato nelle *espressioni composte* per **decretare quali operatori vengono raggruppati *per primi* con i loro operandi**. 

***Più è alto il livello di precedenza, prima questi verranno raggruppati con i loro operandi***.
Prendiamo l'esempio di prima: `4 + 2 * 3`. La moltiplicazione possiede un *livello di precedenza* **maggiore** di quello dell'addizione (rispettivamente `5` e `6`), pertanto la **moltiplicazione verrà raggruppata per prima con i suoi operandi**, quindi verrà valutata come `4 + (2 * 3)`.

#### Associatività degli operatori
Supponiamo ora di avere la seguente espressione composta: `7 - 4 - 1`. L'espressione deve essere valutata come `(7 - 4) - 1`, che fa  `2` oppure `7 - (4 - 1)`, che fa `4`?
Qui sorge un altro problema: siccome entrambi gli operatori di sottrazione **hanno lo stesso *livello di precedenza*** (in particolare sono di *livello 6*), le regole di precedenza *non possono essere usate in questo caso*.

**Se due operatori aventi lo stesso livello di precedenza sono *adiacenti* in una stessa espressione composta**, allora si applicano ***le regole di associatività***: queste sanciscono come ***valutare gli operatori*** (non gli operandi!), se da *sinistra verso destra* o da *destra verso sinistra*. 

Nel caso della espressione `7 - 4 - 1`, siccome l'associatività dell'operazione di sottrazione è da *sinistra verso destra*, l'espressione verrà raggruppata *da sinistra verso destra*, quindi diventa `(7 - 4) - 1`.

#### Tabella di associatività e precedenza degli operatori
La [seguente tabella (Table of operator precedence and associativity)](https://www.learncpp.com/cpp-tutorial/operator-precedence-and-associativity/) sancisce, **per ogni operatore**, il suo *livello di precedenza* e *la sua associatività*.
- Il ***livello di precedenza*** `1` è ***il livello di precedenza massima***, mentre `17` ***è il livello minimo*** - operatori con *livello di precedenza maggiore* saranno **raggruppati per primi**;
- L -> R significa associatività da *sinistra a destra*;
- R -> L significa associatività da *destra a sinistra*.

Nella tabella sono presenti alcuni operatori ripetuti, come per esempio `operator<<`: esso funge sia da ***operatore di inserimento*** e da ***operatore left shift binario***. Il significato di tale operatore **viene determinato in automatico dal compilatore sulla base del tipo degli operandi inseriti**.

#### Uso delle parentesi
Essendo uno degli operatori con *livello di precedenza* più alto, le **parentesi tonde** `()` vengono usate per **raggruppare forzatamente** delle operazioni. Per esempio, normalmente, l'espressione `7 + 4 * 3` viene raggruppata come `7 + (4 * 3)`, ma tramite le parentesi possiamo *forzare* l'espressione `(7 + 4) * 3`. 

Le parentesi possono essere anche usate per **rendere più chiare espressioni che non lo sono di base**, per esempio usandole per specificare il corretto ordine in cui effettuare le operazioni senza dover far ricorso alla tabella delle precedenze.

Una buona regola, molto utilizzata è quella di ***usare parentesi ovunque***, ad eccezione di *addizioni, sottrazioni, moltiplicazioni e divisioni*. Un'altra eccezione a questa regola è quella di non circondare con parentesi il membro di destra di un'assegnazione **in presenza di una singola assegnazione**. 

```cpp
x = (y + z + w);   // singola assegnazione - troppe parentesi
x = y + z + w;     // okay!

x = ((y || z) && w); // singola assegnazione - troppe parentesi
x = (y || z) && w;   // okay!

x = (y *= z); // multiple assegnazioni - okay!
```

##### *Value computation* e *evaluation*
Con il termine ***value computation*** si intende **la valutazione di operatori in una espressione** al fine di ottenere **un risultato**. Le regole di precedenza e associatività vengono applicate per capire in che ordine avviene la *value computation*.

Con il termine ***evaluation*** si intende la **valutazione di *operandi*** (non di *operatori o espressioni*). Per esempio, data l'espressione `a + b`, l'operando `a` verrà *valutato*, producendo un valore, l'operando `b` verrà *valutato*, producendo un valore; questi valori vengono usati per ***value computation*** della somma per mezzo di `operator+`.

#### L'ordine di valutazione degli operandi è *spesso* non specificato
Abbiamo visto che le regole di precedenza e associatività sanciscono come **gli operandi di operatori** devono essere ***raggruppati***. L'espressione
```cpp
a * b + c * d 
```
Verrà ***raggruppata come***
```cpp
(a * b) + (c * d)
```
Se `a` è `1`, `b` è `2`, `c` è `3` e `d` è `4`, questa espressione **verrà sempre valutata `14`**.

Tuttavia, seppure il valore è sempre lo stesso, **le regole di precedenza e associatività ci diranno come gli operandi *vengono raggruppati***, ma **non l'ordine con cui *la value computation* e la *evaluation* degli operandi avviene**.
Questo significa che non si sa quale tra `(a * b)` e `(c * d)` verrà *computata* per prima, e non si sa neanche chi tra `a`, `b`, `c` o `d` verrà *valutata* per prima. 

Per la stragrande maggioranza dei casi, ciò non ha importanza - nel caso della nostra espressione il risultato sarà **sempre `14`**. Tuttavia possono verificarsi dei casi in cui l'ordine degli operatori **è importante** e le ambiguità non sono permesse; consideriamo ad esempio il seguente codice:
```cpp
#include <iostream>

int getValue() {
	std::cout << "Inserisci un valore: ";
	int val {};
	std::cin >> val;
	return val;
}

void printCalc(int a, int b, int c) {
	std::cout << (a + b) * c << '\n';
}

int main() {
	printCalc(getValue(), getValue(), getValue()); // L'ordine conta!
	// Chissà cosa stampa...
	
	return 0;
}
```
Se questo programma viene eseguito ed inseriamo i valori `1`, `2` e `3` ci possiamo aspettare che venga stampato il valore `6`, eppure ***non sempre è così*** - questo è dovuto al fatto che **non è garantito che gli argomenti passati a `printCalc()` siano valutati da sinistra verso destra**, in quanto l'ordine è deciso dal compilatore; infatti, se gli operandi venissero letti da *destra verso sinistra*, il risultato sarebbe `5`!

In modo da garantire la corretta lettura dei valori nel corretto ordine, possiamo rendere il codice non ambiguo nel seguente modo:
```cpp
#include <iostream>

int getValue() {
	std::cout << "Inserisci un valore: ";
	int val {};
	std::cin >> val;
	return val;
}

void printCalc(int a, int b, int c) {
	std::cout << (a + b) * c << '\n';
}

int main() {
	// Prendo i valori in ordine corretto
	int a { getValue() };
	int b { getValue() };
	int c { getValue() };
	
	printCalc(a, b, c); // L'ordine conta!
	// Stampa sicuramente in ordine corretto!
	
	return 0;
}
```

È pertanto ***opportuno non scrivere codice che dipenda dall'ordine di valutazione di operandi***.
> [!warning] Raggruppamento vs. Valutazione
> L'ordine di precedenza e di associatività degli operatori determina solo come ***raggruppare gli operandi coinvolti in operazioni***, ma **non l'ordine in cui le operazioni vengono computate**.
