#### Incrementi e decrementi
Siccome *incrementare e decrementare* una variabile (ossia aggiungere o sottrarre `1` al suo valore) è una cosa molto comune, **esistono degli operatori appositi che eseguono l'incremento o il decremento dell'operando**.

- `operator++` *increment operator* - aggiunge `1` al valore di una variabile;
- `operator--` *decrement operator* - sottrae `1` al valore di una variabile.

È però importante notare che, di ciascun operatore, ne ***esistono due versioni***:
- ***Prefix increment/decrement***: l'operatore è posto ***prima dell'operando*** - il valore viene ***incrementato/decrementato e poi restituito subito dopo***.
- ***Postfix increment/decrement***: l'operatore è posto ***dopo all'operando*** - il valore viene ***copiato, poi incrementato/decrementato ed infine restituito***.

#### *Prefix increment/decrement*
Nel caso di *prefix increment/decrement* il comportamento assunto dall'operatore è esattamente quello previsto: viene ***prima incrementato il valore della variabile*** e ***poi avviene la sua valutazione***.

```cpp
#include <iostream>

int main() {
	int x { 5 };
	int y { ++x }; // Incremento poi valuto. Dopo l'espressione x = 6, y = 6.
	
	std::cout << x << ' ' << y << '\n';
	
	return 0;
}
```
Output:
```
6 6 
```

#### *Postfix increment/decrement*
Nel caso di *postfix increment/decrement*, l'incremento/decremento avviene ***successivamente alla valutazione della variabile***. In particolare: 
- **Viene fatta una copia dell'operando**, e viene messa temporaneamente da parte;
- **Avviene l'incremento/il decremento** dell'operando (*non della copia appena creata!*)
- Nell'espressione, **viene valutata la copia del valore** fatta inizialmente.
Il risultato è che vi è l'impressione che ***l'incremento/il decremento dell'operando avviene dopo la sua valutazione nell'espressione in cui si trova***.
```cpp
#include <iostream>

int main() {
	int x { 5 };
	int y { x++ }; // Valuto poi incremento. Dopo l'espressione x = 6, y = 5.  
	
	std::cout << x << ' ' << y << '\n';
	
	return 0;
}
```
Output:
```
6 5
```
In questo caso, quando viene inizializzato `y` col valore `x++`:
- Il valore attuale di `x`, ossia `5` viene copiato e messo da parte;
- Viene incrementato il valore di `x`, che diventa `6`;
- Viene valutato il valore della copia creata inizialmente, ossia `5` - quindi a `y` assegno `5`.

Altri esempi:
```cpp
#include <iostream>

int main() {
	int x { 5 };
	int y { 5 };
	
	std::cout << x << ' ' << y << '\n';
	std::cout << ++x << ' ' << --y << '\n'; // Prefix - incremento poi stampo
	std::cout << --x << ' ' << ++y << '\n';
	std::cout << x-- << ' ' << y-- << '\n'; // Postfix - stampo poi incremento
	std::cout << x << ' ' << y << '\n';
	std::cout << x++ << ' ' << y++ << '\n';
	std::cout << x << ' ' << y << '\n';
	
	return 0;
}
```
Output:
```
5 5
6 4
5 5
5 5
4 4
4 4
5 5
```

#### Quando usare *postfix* o *prefix*
Nella maggior parte dei casi, non c'è differenza tra l'uso di incrementi/decrementi *prefix e postfix* - tuttavia si preferisce **l'uso *prefix*** siccome più efficienti e il loro comportamento è più facile da comprendere.

Usare *postfix* quando risulta più conciso scrivere un'espressione che userebbe i *prefix*.
```cpp
int main() {
	int x { 0 };
	x++; // Incremento x
	++x; // Incremento x
	
	// Alla fine x vale sempre 2, non c'è differenza.
}
```

#### *Side effects*
Una funzione o un'espressione possiedono un ***side effect*** (*effetto collaterale*) se la loro applicazione provoca **un effetto osservabile** oltre alla produzione di un valore di ritorno.

Tipici *side effect* legati, ad esempio, agli operatori sono quelli di ***modificare il valore dell'operando (o degli operandi) a cui sono applicati***.
```cpp
x = 5; // assegnare un valore a una variabile ne modifica il valore

++x; // incrementare una variabile ne modifica il valore

std::cout << x; // stampare un valore cambia lo stato di ciò che viene visualizzato a schermo.
```

Esistono operatori che *non hanno side effects*, come per esempio gli [[6.2 ~ Arithmetic operators|operatori aritmetici]], che si limitano puramente ad ottenere un valore di ritorno senza modificare gli operandi.

#### I *side effects* possono causare problemi di valutazione
In alcuni casi, i *side effect* dovuti agli operatori possono causare problematiche.
Per esempio:
```cpp
#include <iostream>

int add(int x, int y) {
	return x + y;
}

int main() {
	int x { 5 };
	
	// Non so in che ordine verranno passati gli argomenti: 5, 6 oppure 6, 6?
	int res { add(x, ++x) }; // Undefined behavior!
	std::cout << res << '\n';
	
	return 0;
}
```
Siccome C++ **non definisce l'ordine di valutazione degli argomenti**, non è dato sapere chi viene valutato per prima: 
- se viene valutato per primo *quello di sinistra* allora la chiamata sarà `add(5, 6)` che fa `11`;
- se viene valutato per primo *quello di destra* allora la chiamata sarà `add(6, 6)` che fa `12`.

Nella maggior parte dei casi, C++ ***non definisce l'ordine in cui i side effect avvengono***, causando molto spesso [[1.6 ~ Uninitialized variables and undefined behavior|undefined behavior]] nei casi in cui ***si verifichino più side effect nella stessa espressione***. 
Se prendiamo come esempio l'espressione `x + ++x` fornirà valori diversi sulla base del compilatore che viene usato. 

> [!warning] Espressioni e *side effects*
> Per evitare ***undefined behavior*** è opportuno che, per ogni espressione ***gli operandi che subiscono side effects in tale espressione vi compaiano una e una sola volta***.
