Il ***conditional operator*** (**operatore condizionale**) `operator?:` è **l'unico operatore ternario di C++** - infatti viene anche chiamato ***operatore ternario***. 

Questo operatore permette di **scrivere in forma ridotta un [[4.10 ~ Introduction to if statements|if-else statement]]**.
Ricapitolando, un *if-else statement* ha la seguente forma:
```cpp
if (condition)
	statement1;
else
	statement2;
```
Se la `condition` è `true`, allora viene eseguito `statement1`, altrimenti viene eseguito `statement2`. L'uso di `else` e `statement2` è *facoltativo* (se non specificati è un *if statement*).

`operator?:` viene usato nella seguente forma:
```cpp
condition ? expression1 : expression2;
```
Se la `condition` è `true` viene valutata `expression1`, altrimenti viene valutata `expression2`. In questo caso `:` e `expression2` **sono obbligatori**.

Un *if-else statement* così formato:
```cpp
if (x > y)
	max = x;
else
	max = y;
```
Può essere riscritto come:
```cpp
max = ((x > y) ? x : y);
```
Che risulta molto più compatto!

#### L'operatore condizionale viene valutato come parte di un'espressione
Siccome `operator?:` **viene valutato come parte di un'espressione** (*in quanto operatore*) esso può ***essere usato nei casi in cui venga richiesta un'espressione***.

Se gli operandi sono *[[5.5 ~ Constant Expressions|constant expressions]]* **l'operatore ternario può essere usato in contesti che richiedono *constant expressions*** (per esempio nell'inizializzazione di [[5.6 ~ Constexpr variables|constexpr]]) - questo risulta molto utile in molti casi in cui si vuole inizializzare una `constexpr` a un valore che dipende da valori costanti (per esempio inizializzare un valore sulla base dell'architettura della macchina su cui viene compilato il programma - non è possibile fare ciò tramite un *if-else* in modo diretto).

#### `operator?:` va circondato da parentesi
L'operatore condizionale ha un **basso [[6.1 ~ Operator precedence and associativity#Precedenza degli operatori|livello di precedenza]]** rispetto alla maggior parte degli altri operatori. Al fine di permettere la corretta esecuzione dello *statement* in cui esso viene usato, viene **spesso circondato da parentesi** - nei casi in cui questo non viene fatto il risultato è spesso qualcosa di inatteso.

```cpp
#include <iostream>

int main() {
	int x { 3 };
	std::cout << (x < 0) ? "Negativo\n" : "Non negativo\n";

	return 0;
}
```
Ci aspettiamo che venga stampato `"Non negativo"` ed invece viene stampato `0` (???).
- Viene valutato `x < 0`, che risulta `false` in quanto `x` vale `3`.
- `operator<<` **ha precedenza maggiore** dell'operatore ternario; dopo il raggruppamento, l'espressione diventa
```cpp
(std::cout << false) ? "Negativo\n" : "Non negativo\n";
```
- Viene valutato `std::cout << false`, che [[4.9 ~ Boolean values#Stampa di valori booleani|stampa 0]];
- Viene valutata l'espressione `std::cout ? "Negativo\n" : "Non negativo\n";` - essendo `std::cout`, va convertito in `bool`. Stranamente `std::cout` ha una *opportuna conversione a `bool`*, che restituisce `false`.
- L'espressione diventa quindi `false ? "Negativo\n" : "Non negativo\n";`, che ha come risultato il *literal* `"Non negativo\n"` - essendo un *literal*, viene scartato.

Per evitare valutazioni errate come abbiamo appena visto ***l'operatore ternario (inclusi i suoi operandi) vanno sempre circondati da parentesi***.
> [!tip] Parentesi con `operator?:`
> Per evitare errori di valutazione a causa di precedenza ed associatività è **sempre opportuno circondare `operator?:` e i suoi operandi con le parentesi tonde `()`**. 
> È anche opportuno circondare con parentesi **la condizione che deve essere valutata**.
> Il risultato finale dovrebbe mantenere la seguente forma:
> ```cpp
> ((condition) ? exp1 : exp2);
>  ```

#### Le espressioni devono essere *matching* o *convertible*
Lo standard C++ per la *valutazione di tipi di dato* ha la necessità che, per quanto riguarda `operator?:` **debba valere una di queste due regole**:
- *Il tipo di dato del secondo e del terzo operando deve **corrispondere*** (ossia essere lo stesso);
- *Il compilatore deve essere in grado di **convertire il tipo di dato del secondo o terzo operando** per ottenere corrispondenza di tipo*.
La seconda regola, non conoscendo ancora **le regole alla base della conversione tra tipi** può causare **comportamenti inattesi**.

```cpp
#include <iostream>

int main()
{
	// OK: entrambi int
    std::cout << (true ? 1 : 2) << '\n';
	
	// OK: converto 1 a double -> entrambi double
    std::cout << (false ? 1 : 2.2) << '\n'; 
	
	// ATTENZIONE: -1 viene convertito a unsigned int e va out of range
	// Opportuno qui convertire 2u con static_cast a signed.
    std::cout << (true ? -1 : 2u) << '\n';

	// Compile error: non posso convertire 1 a std::string o "Ciao!" a int.
	std::cout << (true ? 1 : "Ciao!") << '\n';
    return 0;
}
```

#### Uso dell'operatore ternario
L'operatore ternario viene usato molto spesso in operazioni semplici e dirette, come per esempio:
- Inizializzare una variabile a *uno di due valori*;
- Assegnare a una variabile *uno di due valori*;
- Passare a una funzione *uno di due valori*;
- Stampare *uno di due valori*;
- Restituire *uno di due valori* da una funzione.
Per espressioni complesse l'uso di `operator?:` è sconsigliato a favore di un *if-else*.
