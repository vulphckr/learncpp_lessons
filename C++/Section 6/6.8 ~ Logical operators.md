Gli [[6.7 ~ Relational operators and floating point comparisons|operatori relazionali]] riescono a controllare **una sola condizione alla volta**. Tuttavia in molti casi abbiamo bisogno di controllare *se più condizioni sono vere allo stesso momento*, oppure se *solo una di più condizioni viene rispettata*.

I ***logical operators*** (*operatori logici*) permettono di ***controllare più condizioni contemporaneamente***. Esistono ***tre*** operatori logici:
- `operator!` - *logical NOT*;
- `operator&&` - *logical AND*;
- `operator||` - *logical OR*.
Si applicano tutti **esclusivamente a operandi di tipo `bool`**.
#### `operator!` - *Logical NOT*
Abbiamo già visto questo operatore quando abbiamo parlato di [[4.9 ~ Boolean values|variabili booleane]].
`operator!` è un **operatore unario** che **inverte il significato dell'operando da `true` a `false` e viceversa**.

Un problema legato a questo operatore è che ha [[6.1 ~ Operator precedence and associativity|livello di precedenza]] ***molto alto***, pertanto verrà raggruppato prima di molti altri operatori, causando problemi nei casi in cui questo non è voluto.
```cpp
#include <iostream>

int main() {
	int x { 5 };
	int y { 7 };
	
	if (!x > y) 
		std::cout << x << " è più piccolo di " << y << '\n';
	else
		std::cout << x << " è più grande di " << y << '\n';
}
```
Questo programma stampa `5 è più grande di 7`, che non è chiaramente vero, per la seguente motivazione:
- Il condizionale `!x > y` viene raggruppato, per ordine di precedenza, in `(!x) > y`.
- `(!x)` viene valutato come `0`, in quanto `!5` fa `0`. 
- L'espressione diventa `0 > 7` che  `false`, pertanto si esegue l'espressione contenuta dentro `else`

È pertanto necessario fare attenzione *a quando si vuole applicare `operator!`*, circondando eventualmente con parentesi la condizione da invertire.
```cpp
#include <iostream>

int main() {
	int x { 5 };
	int y { 7 };
	
	if (!(x > y)) 
		std::cout << x << " è più piccolo di " << y << '\n';
	else
		std::cout << x << " è più grande di " << y << '\n';
}
```
Circondando la condizione con parentesi si ottiene il comportamento corretto.

#### `operator||` - *Logical OR*
`operator||`, l'operatore di *OR logico*, è un **operatore binario** che viene usato ***per controllare se almeno una delle due condizioni è `true`***. In particolare, **se *uno o entrambi* degli operandi è `true`, l'operatore restituirà `true`**.

```cpp
#include <iostream>

int main() {
	std::cout << "Inserisci un numero: ";
	int x {};
	std::cin >> x;

	if (x == 0 || x == 1)
		std::cout << "Hai inserito 0 oppure 1.\n";
	else
		std::cout << "Non hai inserito 0 oppure 1.\n";
	return 0;
}
```
La condizione `x == 0 || x == 1` restituirà `true` se abbiamo inserito `0` oppure `1`.

È possibile concatenare più `operator||` consecutivamente.
```cpp
if (x == 0 || x == 1 || x == 2 || x == 3)
     std::cout << "Hai inserito 0, 1, 2 o 3.\n";
```

L'operatore di *OR logico* **non si deve confondere con l'operatore di *OR Bitwise***, che vedremo in seguito quando parleremo di *bit manipulation*.

#### `operator&&` - *Logical AND*
`operator&&`, l'operatore di *AND logico*, è un **operatore binario** che viene usato ***per controllare se entrambe le due condizioni sono `true`***. In particolare `operator&&` restituisce `true` **se e solo se entrambi gli operandi sono `true`**.

Possiamo usare `operator&&` per controllare se un valore si trova in *un range di valori*:
```cpp
#include <iostream>

int main() {
	std::cout << "Inserisci un numero: ";
	int x {};
	std::cin >> x;

	if (x > 10 && x < 20)
		std::cout << "Il numero inserito sta tra 10 e 20.\n";
	else
		std::cout << "Il numero inserito non sta tra 10 e 20.\n";
	return 0;
}
```
La condizione `x > 10 && x < 20` restituirà `true` se il numero è maggiore di `10` e minore di `20` allo stesso momento. Se inseriamo per esempio `31` esso è maggiore di `10`, ma non minore di `20` - quindi non si trova tra `10` e `20`.

È possibile concatenare più `operator&&` consecutivamente.
```cpp
if (x > 10 && x < 20 && x != 16)
     std::cout << "Il numero inserito sta tra 10 e 20 e non è 16.\n";
```

Anche in questo caso, l'operatore di *AND logico* **non va confuso con l'operatore di *AND Bitwise***, che vedremo anch'esso quando parleremo di *bit manipulation*.

#### *Short-Circuit evaluation*
Abbiamo visto che `operator&&` restituirà `true` se e solo se **entrambi gli operandi sono `true`**. Tuttavia, il *logical AND* sa che **se l'operando di sinsitra risulta `false`** allora ***egli deve valutare tutta la condizione come `false`*** qualsiasi sia il valore dell'operando di destra.
In particolare, se l'operando di sinistra è `false`, **l'operando di destra non viene neanche valutato**, ***e viene restituito direttamente `false`***. 

Questo avviene anche per `operator||` - se l'operando di sinistra è `true`, tutta la condizione verrà valutata come `true`, **scartando la valutazione dell'operando di destra**.

Questa procedura da parte degli operatori è detta ***short-circuit evaluation***.
La *short-circuit evaluation* ci da un altra possibilità per spiegare che **non è opportuno inserire *[[6.4 ~ IncrementDecrement operators, and side effects#*Side effects*|operatori che causano side effects]]* all'interno di espressioni composte**.

```cpp
if (x == 1 && ++y == 2)
	// fai qualcosa...
```
In questo caso, se `x` è diverso da `1`, tutta l'espressione viene valutata come `false`, ma **l'operando di destra non viene mai valutato, e il *[[6.4 ~ IncrementDecrement operators, and side effects#*Prefix increment/decrement*|preincremento]]* su `y` non avviene**.

> [!warning] ***Short-circuit evaluation***
> Non è consigliato l'uso di operatori che causano *side-effects* con `operator&&` e `operator||` a causa della loro possibile *non-esecuzione* a causa di *short-circuit evaluation*.

> [!tip]
> Seppur [[6.1 ~ Operator precedence and associativity#L'ordine di valutazione degli operandi è *spesso* non specificato|l'ordine di esecuzione degli operandi non è specifico]], gli operatori di OR e AND logici **valutano i loro operandi sempre da sinistra verso destra**.

#### Uso misto di OR e AND logici
Usare un misto di `operator&&` e `operator||` all'interno di espressioni è possibile, ma **bisogna fare attenzione all'ordine in cui essi vengono valutati**.

Seppur potrebbero sembrare speculari, come `operator+` e `operator-`, `operator&&` e `operator||` hanno ***diversi livelli di precedenza*** - in particolare, gli `operator&&` verranno valutati prima degli `operator||` in quanto i primi hanno un [[6.1 ~ Operator precedence and associativity|livello di precedenza]] **maggiore rispetto ai secondi**.

Siccome avviene spesso che quando si scrive una certa condizione la si scrive come ci si aspetta che venga valutata, potrebbe avvenire che, a causa della differenza dei livelli di precedenza, l'espressione finale **non sia quella che ci si aspetta**.

È *fortemente consigliabile* **circondare con parentesi tonde `()` le espressioni che devono essere valutate per prime**, in modo da stabilire il corretto ordine di valutazione.

Per esempio, al posto di scrivere `value1 && value2 || value3 && value4`, è opportuno scrivere `(value1 && value2) || (value3 && value4)`, nonostante le due espressioni siano equivalenti.

#### Leggi di De Morgan
Molto spesso i nuovi programmatori pensano che il *NOT logico* può essere distribuito tra ciò che c'è tra parentesi, come ad esempio `!(x && y)` distribuito come `!x && !y` - ***tuttavia non è così***.

Le ***leggi di De Morgan*** ci dicono come *distribuire correttamente il NOT logico* all'interno di una parentesi.
- `!(x && y)` diventa `!x || !y`;
- `!(x || y)` diventa `!x && !y`;
In breve, quando il *NOT logico* deve essere distribuito tra parentesi, basta porre a *NOT* ciascun elemento posto tra parentesi e ***invertire gli AND logici a OR logici e viceversa!***

#### Un operatore per *Logical XOR*
Il ***logical XOR*** è un operatore **binario** che restituisce `true` se ***un numero dispari di condizioni è `true`***.

C++ **non fornisce direttamente un operatore per il *logical XOR*** (ne esiste invece uno per il *bitwise XOR*) poichè esso **non ha la proprietà di *short-circuit evaluation***; tuttavia, `operator!=`, **quando ha come argomento dei valori di tipo `bool`**, si comporta **esattamente come il *logical XOR***.
```cpp
if (a != b) // considerati a e b di tipo bool
	...
```
Anche questo operatore è eventualmente concatenabile:
```cpp
if (a != b != c) // a XOR b XOR c
	...
```

Se gli operandi di `operator!=` non sono di tipo `bool` essi possono essere convertiti tramite `static_cast` oppure tramite l'uso di un doppio `operator!` (il primo per effettuare una conversione implicita a `bool`, il secondo per ottenere il valore effettivo).
***Questo è possibile se i tipi di partenza possono essere convertiti a `bool`***.
```cpp
if (static_cast<bool>(a) != static_cast<bool>(b))
	...

if (!!a != !!b)
	...
```

#### Rappresentazione alternativa di `operator&&`, `operator||` e `operator!`
Abbiamo visto che, nella maggior parte dei casi, ***gli operatori di C++ vengono rappresentati per mezzo di simboli***. Siccome, storicamente, non tutte le tastiere possedevano i simboli necessari a rappresentare questi simboli, C++ ha introdotto **una nomenclatura alternativa per alcuni operatori**, per mezzo di *keyword specifiche*. Nel caso degli *operatori relazionali*, questi sono:
- `or`, usabile al posto di `operator||`;
- `and`, usabile al posto di `operator&&`;
- `not`, usabile al posto di `operator!`.
`(!a || (b && c))` può essere espresso come `(not a or (b and c))`.

Seppur disponibili, la maggior parte dei programmatori consiglia l'uso ***dei simboli rispetto alle keyword***, in quanto più conciso e più chiaro dal punto di vista documentativo.
