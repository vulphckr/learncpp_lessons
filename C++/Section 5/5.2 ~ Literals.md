I ***[[1.9 ~ Introduction to literals and operators#*Literals*|literals]]*** sono valori che **vengono inseriti direttamente nel codice**.
```cpp
int x { 5 }; // 5 è un literal di tipo int
double d { 6.7 }; // 6.7 è un literal di tipo double
bool myBool { true }; // true è un literal di tipo bool
std::cout << "Hello world!" << '\n';
// "Hello world!" è un literal di tipo stringa C-type, mentre '\n' è un literal di tipo char.
```

##### Tipi di literal
Esistono diversi tipi di ***literals di default***, che vengono automaticamente interpretati dal compilatore in determinati tipi di dato:
- Interi: *literals* rappresentanti numeri interi, come ad esempio `3`, `0` e `-3`. Vengono interpretati come `int`.
- Decimali: *literals* rappresentanti numeri decimali, come ad esempio `3.4` o `-9.9`. Vengono interpretati come `double` (non `float`!)
- Booleani: `true` o `false`. Vengono interpretati come `bool`.
- Caratteri: *literal* rappresentanti caratteri o [[4.11 ~ Chars#Escape sequences|sequenze di escape]], come ad esempio `'a'` o `'\n'`. Vengono interpretati come `char.`
- C-Style Strings: *literal* rappresentanti stringhe, ossia sequenze di caratteri tra doppi apici, come ad esempio `"Hello world!"`. Vediamo in seguito come vengono interpretate.

Se si vuole un *literal* di un tipo diverso da quello di default, è necessario **apporvi un suffisso**. Il suffisso inserito determina il tipo di dato del *literal*. In questa tabella sono presenti tutti i suffissi possibili e i corrispettivi tipi di dato.
![[cpp_literal_suffixes.png]]
Tuttavia, nella maggior parte dei casi, i suffissi non sono necessari (ad eccezione del suffisso `f` per i `float`).

I suffissi non sono case sensitive, ma si preferisce la versione maiuscola. Si hanno le seguenti eccezioni:
- `s` e `sv` devono essere minuscoli
- Due caratteri uguali consecutivi devono avere lo stesso casing (o entrambe maiuscole o entrambe minuscole).

#### Integral *literals*
Generalmente, per gli integrali, **non è necessario specificare suffissi**. Questo poichè il compilatore convertirà automaticamente il *literal*, di tipo di default `int`, al tipo appropriato alla situazione in cui viene usato.
```cpp
int main() {
	unsigned int a { 5 }; // OK: conversione da int a unsigned int
	long l { 4 }; // OK: conversione da int a long
	
	unsigned int a2 { 5u }; // OK: literal di tipo unsigned int
	long l2 { 4L }; // OK: literal di tipo long
}
```

#### Floating point *literals*
Siccome i *literal* di numeri avente parte frazionaria hanno tipo di dato `double` al fine di rendere tale valore memorizzabile in un `float` va **necessariamente** aggiunto il suffisso `F` o `f`. Nel caso si provi a memorizzare un *literal* decimale in un contesto dove viene richiesto un valore `float` e non si specifica il suffisso `f`, il compilatore restituirà un ***warning*** dovuto a perdita di precisione dalla conversione implicita da `double` a `float`.
```cpp
int main() {
	double d { 5.0 }; // OK (default double)
	float f { 5.0f }; // OK (suffisso f)
	
	float nf { 5.0 }; // Warning: conversione da literal double a valore float
}
```

#### Notazione scientifica per *literal* floating point
Ci sono due modi per scrivere i *literal* floating point;
- Nella forma standard, ossia come numeri decimali;
```cpp
double pi { 3.14 };
double e { 2.71 };
double g { 9.81 };
```
- In [[4.7 ~ Introduction to scientific notation|notazione scientifica]], specificando l'esponente del 10 tramite `e`:
```cpp
double numAvogadro { 6.02e23 }; // Significa 6.02 x 10^23
double caricaProtone { 1.6e-19 }; // Significa 1.6 x 10^-19
```

#### String *literals*
In programmazione, una ***stringa*** è un insieme di caratteri in succesione usato per la rappresentazione di testo. Nel primissimo programma che abbiamo scritto:
```cpp
#include <iostream>

int main() {
	std::cout << "Hello world!" << '\n';
	return 0;
}
```
`"Hello world!"` è ***uno string literal***. Ogni *string literal* viene posto tra doppi apici `""`, opposti ai caratteri, posti invece tra singoli apici `''`. 

In quanto le stringhe sono molto utilizzate in programmazione, ogni linguaggio di programmazione moderno ha una propria implementazione delle stringhe, spesso come tipo di dato fondamentale. In C++ le stringhe ***non sono un tipo di dato fondamentale***, e vengono rappresentate tramite un tipo di dato particolarmente complesso da usare - nel linguaggio C++ le stringhe vengono chiamate ***C-style strings***, poichè ereditate dal C.

Introduciamo due proprietà non ovvie delle *C-style strings*:
1) **Tutti gli *string literals* possiedono un *null terminator* implicito**. Prendendo come esempio la stringa `Ciao`, potrebbe sembrare che essa abbia solo 4 caratteri, ma in realtà ne ha 5: `'C'`, `'i'`, `'a'`,`'o'` e **`'\0'`** - quest'ultimo carattere è una [[4.11 ~ Chars#Escape sequences|escape sequence]] chiamata ***null terminator***, che indica il termine di una stringa.
	Una stringa che termina con un ***null terminator*** viene detta ***null-terminated***.
2) A differenza di molti altri *literal*, gli *string literal* sono ***oggetti `const`*** creati **all'inizio dell'esecuzione del programma** e di cui viene **garantita l'esistenza per tutta la sua esecuzione**. Questo significa che ***i literal C-Style string esisteranno sempre una volta che vengono specificati***.

#### Magic Numbers
Un ***magic number*** è un *literal*, spesso numerico (ma può essere anche testuale), che non ha un significato preciso nel contesto in cui viene usato o il cui valore deve essere successivamente cambiato.
```cpp
const int studentiInScuola { numeroClassi * 30 };
setMax(30);
```
In questi casi, `30` che cosa significa? Se abbiamo scritto noi il codice magari possiamo anche saperlo, ma una persona esterna che legge questo codice non ha la minima idea di che valori siano. in quanto non vi è un commento che spiega perchè vada usato proprio `30` in entrambi i casi - soprattutto nel secondo, in cui dobbiamo vedere la definizione di `setMax()` per capire cosa sta succedendo. 

In programmi più complessi l'uso di *magic number* può portare a molte incomprensioni **se non documentati**. Inoltre vi è un altro problema: cosa succede se, in un dato momento, il valore specificato da un *magic number* deve cambiare? Dobbiamo aggiornare tutti i *literal* corrispondenti, ma se non sono documentati è difficile anche capire quali nell'esattezza! Questa procedura richiederebbe più tempo di quello necessario.

Pertanto l'uso di *magic number* senza documentazione è considerato una ***bad practice***.
Tuttavia, entrambi i problemi possono essere risolti per mezzo dei valori `const`: inserendo in una apposita variabile costante il *magic number* (e volendo aggiungendo pure un commento), stiamo dando del contesto a tale valore tramite l'identificatore di tale variabile, così che, nel caso di incomprensioni o cambiamenti, basta guardare o modificare la variabile costante associata al valore. 

I *magic numbers* possono anche non essere *numeri*, ma anche *stringhe* o *caratteri*.
```cpp
int main() {
	printAppName("MyApp"); 
	// Magic Number di tipo stringa - il nome dell'app può essere usato anche altrove!
}
```

Generalmente ***non*** sono considerati *magic numbers*:
- *Literal* usati in contesti **ovvi**, come ad esempio contatori o per effettuare conversioni di unità di misura;
- *Literal* usati in sequenza (ossia prima uso `1`, poi uso `2`...).

La ***good practice*** è comunque quella di **evitare i magic numbers**, preferendo altri modi per introdurre tali valori nel codice come ad esempio le `constexpr`.
