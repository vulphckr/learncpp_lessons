Abbiamo visto, nella [[5.2 ~ Literals|lezione dei literal]], i ***C-Style String Literals***, ossia i *literals* usati per rappresentare sequenze di caratteri.
Seppur l'uso dei ***literals*** di questo tipo non hanno alcun problema, l'uso di ***variabili*** di questo tipo è ***sconsigliato***, in quanto:
- Si comportano in modo particolare;
- Sono difficili da usare (ad esempio non è possibile effettuare assegnazioni di nuovi valori);
- Sono pericolose (copiare stringhe in variabili che non sono abbastanza grandi da poterle contenere causa ***undefined behavior***).

Fortunatamente C++ introduce **due nuovi tipi** per gestire le stringhe, i quali sono molto più semplici e più sicuri da usare. Questi sono `std::string` ed `std::string_view`. Questi **non sono tipi fondamentali**, a differenza dei tipi che abbiamo visto finora, ma il loro uso è così semplice che possiamo spiegarlo anche in questo momento.

#### Introduzione a `std::string`
Il modo più facile per operare con oggetti di tipo *stringa* (che da ora chiameremo *stringhe* per semplicità), è tramite il tipo `std::string`, contenuto nell'header `<string>`.

Possiamo creare variabili di questo tipo nello stesso modo in cui abbiamo fatto per tutti i tipi di dato visti finora:
```cpp
#include <string> // per std::string

int main() {
	std::string myString {};
	
	return 0;
}
```
La [[1.4 ~ Variable assignment and initialization#Value-initialization e zero-initialization|value-initialization]] di una variabile di tipo `std::string` è una stringa vuota, quindi in questo caso `myString` viene inizializzata a una stringa vuota.

Possiamo inizializzare o assegnare valori alle variabili di tipo `std::string`.
```cpp
#include <string> // per std::string

int main() {
	std::string myString { "Ciao!" }; // Inizializzo myString a "Ciao!"
	myString = "Come va?"; // Assegno "Come va?" a myString
	
	return 0;
}
```

Sottoforma di stringhe, qualsiasi valore numerico viene trattato **come testo, non come numero**, e pertanto non è possibile manipolarli come se fossero numeri (effettuando per esempio operazioni aritmetiche). C++ non convertirà automaticamente stringhe a interi o decimali, anche se ci sono metodi per forzare tale conversione. 

#### Output di stringhe con `std::cout`
Variabili di tipo `std::string` visualizzeranno il loro valore come output tramite `std::cout`, in modo simile a come abbiamo visto per ogni altro tipo di dato.
```cpp
#include <string> // per std::string
#include <iostream>

int main() {
	std::string myString { "Ciao!" }; // Inizializzo myString a "Ciao!"
	std::cout << myString << " Come va?" << '\n';
	
	return 0;
}
```
Output:
```
Ciao! Come va?
```

Se la variabile memorizza una stringa vuota, non verrà stampato niente.
```cpp
#include <string> // per std::string

int main() {
	std::string stringaVuota { }; // La stringa memorizzata è vuota.
	std::cout << '[' << stringaVuota << ']' << '\n';
	
	return 0;
}
```
Output:
```
[]
```

#### `std::string` può memorizzare stringhe di lunghezza variabile
Una delle funzioni più utili delle variabili del tipo `std::string` è la **memorizzazione di stringhe di diversa grandezza**. È possibile infatti memorizzare stringhe di qualsiasi grandezza: da vuote alle migliaia di caratteri. 

Questo è dovuto dal fatto che quando `std::string` non ha abbastanza memoria per memorizzare una stringa, **ne richiede dell'altra** - questa abilità di poter richiedere dinamicamente memoria prende il nome di **allocazione dinamica della memoria**, che vedremo in seguito.

#### Input di stringhe con `std::cin`
L'input di `std::string` tramite `std::cin` non viene eseguito in modo normale, a causa di come quest'ultimo si comporta. Infatti, [[1.5 ~ Introduction to iostream cout, cin, endl#`std cin`|essendo buffered]], se inseriamo una stringa contenente *whitespace*, questa verrà spezzata in due stringhe!
```cpp
#include <string> // per std::string

int main() {
	std::cout << "Inserisci il tuo nome completo: ";
	std::string nome { };
	std::cin >> nome;
	
	std::cout << "Inserisci il luogo di nascita: ";
	std::string luogoNascita { };
	std::cin >> luogoNascita;
	
	std::cout << "Ciao, tu sei " << nome 
		<< " e sei nato a " << luogoNascita << '\n';
	
	return 0;
}
```
Se inserisco `Mario Rossi` e poi `Cesena`, avrò il seguente (*inaspettato*) output:
```
Inserisci il tuo nome completo: Mario Rossi
Inserisci il luogo di nascita: Ciao, tu sei Mario e sei nato a Rossi
```
L'output risultante è dovuto al fatto che `std::cin` estrae tutti i caratteri **fino al primo *whitespace* che incontra**, lasciando i caratteri rimanenti all'interno del suo buffer per una estrazione successiva.

In questo caso, quando abbiamo inserito `Mario Rossi`, alla prima estrazione verrà inserito `Mario` all'interno di `nome`, lasciando ` Rossi` nel buffer per la prossima estrazione; dopodichè alla seconda estrazione inserirà `Rossi` all'interno di `luogoNascita` anzichè chiederci il luogo di nascita - infine effettua la stampa e il programma termina.

#### Usare `std::getline()` per l'inserimento di testo
Per leggere **un'intera linea** dall'input, è necessario utilizzare la funzione `std::getline()`.
Essa richiede **due argomenti**: il primo è `std::cin` (o *una stream di input*) mentre il secondo è la variabile in cui salvare la linea letta.

```cpp
#include <string> // per std::string e std::getline

int main() {
	std::cout << "Inserisci il tuo nome completo: ";
	std::string nome { };
	std::getline(std::cin >> std::ws, nome);
	
	std::cout << "Inserisci il luogo di nascita: ";
	std::string luogoNascita { };
	std::getline(std::cin >> std::ws, luogoNascita);
	
	std::cout << "Ciao, tu sei " << nome 
		<< " e sei nato a " << luogoNascita << '\n';
	
	return 0;
}
```
Se inserisco `Mario Rossi` e poi `Cesena`, avrò il seguente output:
```
Inserisci il tuo nome completo: Mario Rossi
Inserisci il luogo di nascita: Cesena
Ciao, tu sei Mario e sei nato a Cesena
```
Adesso il programma funziona come previsto!

#### Che cos'è `std::ws`?
Nell'esempio appena fatto, nel primo argomento di `std::getline()`, oltre a `std::cin` appare anche `std::ws`: che cos'è quest'ultima cosa?

[[4.8 ~ Floating point numbers#Output di valori *floating point*|Abbiamo visto]] che cos'è **un *output manipulator***: è qualcosa che permettono di cambiare il modo in cui l'output viene visualizzato - abbiamo visto per esempio `std::setprecision()`, che cambia la precisione di visualizzazione di numeri floating point, oppure `std::boolalpha` che cambia la visualizzazione di un booleano da numerica a letterale.

Oltre agli *output manipulator*, sono supportati anche ***input manipulator***, che cambiano il modo in cui l'input di dati viene processato. `std::ws` è proprio un *input manipulator*, il quale comunica a `std::cin` di **ignorare i *leading whitespace* presenti nell'input** - ossia i *whitespace* posti all'inizio della stringa di input.

Vediamo perchè questo è utile, supponiamo di avere un programma del genere:
```cpp
#include <iostream>
#include <string>

int main()
{
    std::cout << "Scegli un numero: ";
    int sceltaNumero {};
    std::cin >> sceltaNumero;

    std::cout << "Inserisci il tuo nome completo: ";
    std::string nomeCompleto {};
    std::getline(std::cin, nomeCompleto); // manca std::ws!

    std::cout << "Ciao, " << nomeCompleto 
	    << ", hai scelto " << sceltaNumero << '\n';

    return 0;
}
```
Inserendo `2`, l'output del programma è:
```
Scegli un numero: 2
Inserisci il tuo nome completo: Ciao, , hai scelto 2
```
Fino alla scelta del numero va tutto bene, ma in seguito l'inserimento del nome completo viene completamente saltato, con la stampa dell'output finale priva del nome in quanto la stringa della variabile `nomeCompleto` è vuota.

Questo accade per il seguente motivo:
- Quando ci viene richiesto l'inserimento del numero **e premiamo invio**, nel buffer di `std::cin` sarà presente `"2\n"` - il valore `2` viene estratto e messo in `sceltaNumero` e nel buffer rimarrà solo `"\n"`.
- Quando `std::getline()` effettua l'estrazione, all'interno del buffer di `std::cin` troverà `"\n"` e penserà che abbiamo inserito una stringa vuota - l'inserimento viene quindi saltato.

Possiamo risolvere il programma precedente semplicemente usando `std::ws` come *input manipulator*, in modo che prima dell'estrazione, ogni *leading whitespace* nel buffer di `std::cin` venga scartato.
```cpp
#include <iostream>
#include <string>

int main()
{
    std::cout << "Scegli un numero: ";
    int sceltaNumero {};
    std::cin >> sceltaNumero;

    std::cout << "Inserisci il tuo nome completo: ";
    std::string nomeCompleto {};
    std::getline(std::cin >> std::ws, nomeCompleto); // ora è presente!

    std::cout << "Ciao, " << nomeCompleto 
	    << ", hai scelto " << sceltaNumero << '\n';

    return 0;
}
```
Output inserendo `2` e `Mario Rossi`:
```
Scegli un numero: 2
Inserisci il tuo nome completo: Mario Rossi
Ciao, Mario Rossi, hai scelto 2
```
Ora funziona!

#### Lunghezza di una `std::string`
Se vogliamo sapere quanto lunga è una stringa, possiamo chiederlo direttamente alla stringa. 
```cpp
#include <iostream>
#include <string>

int main() {
	std::string nome { "Mario" };
	std::cout << "La stringa è lunga: " << nome.length() << '\n';
	
	return 0;
}
```
Anche se `std::string` è *null-terminata* ([[5.2 ~ Literals#String *literals*|qui il significato]]) il carattere terminatore *non verrà contato* nella lunghezza della stringa.

Notiamo anche come non abbiamo chiesto la lunghezza della stringa tramite `length(nome)`, ma come `nome.length()`. Questo perchè `length()` è una **funzione che è legata strettamente a `std::string`**, chiamata ***member function***. Siccome `length()` è definita all'interno di `std::string`, spesso si può trovare scritta come `std::string::length()`.

Inoltre, `std::string::length()` ritorna un **valore unsigned integral**, probabilmente di tipo `size_t` - per poterlo utilizzare all'interno di una variabile è necessario usare `static_cast`.
```cpp
std::string nome { "Mario" };
int lunghezza { static_cast<int>(nome.length()) };
```

#### Inizializzare, passare per valore e ritornare una `std::string` è costoso
Quando una `std::string` viene inizializzata, **una copia della stringa usata come valore di inizializzazione**. Questa è un'operazione, per cui va minimizzato il numero di volte che viene fatta. 

Passare a una funzione un argomento di tipo `std::string` *per valore*, i parametri relativi all'argomento passato **devono essere inizializzati** pertanto viene effettuata **una copia dell'argomento per inizializzare il parametro**, che come abbiamo detto è costosa. 

Passare *per valore* una `std::string` a una funzione ***è sconsigliato*** in quanto costoso.
È preferibile passare invece una `std::string_view`, che vedremo nella prossima lezione.

Quando una funzione restituisce un valore al chiamante, tale valore viene spesso **copiato dalla funzione al chiamante**. Quindi potremmo aspettarci che è sconsigliabile avere una funzione che restituisca `std::string` siccome sarebbe un'operazione costosa, ma in realtà non è sempre così - va bene restituire una `std::string` se:
- È una variabile locale presente all'interno della funzione;
- È una `std::string` restituita da un'altra funzione;
- È una `std::string` temporanea che fa parte dello statement di return.
In ogni altro caso verrà effettuata una copia costosa ed è meglio evitare.

#### Literal di `std::string`
Abbiamo visto che, di default, qualsiasi stringa *literal* (ossia collezione di caratteri posta tra doppi apici `"`), verrà interpretata come ***C-Style string literal***.

Se invece vogliamo interpretare una stringa *literal* come `std::string` è necessario apporre il suffisso `s` alla stringa. La `s` **deve essere minuscola**. Nello scope in cui tale *literal* viene interpretato come `std::string` **deve essere presente una direttiva `using namespace std::string_literals`** (che è uno dei rari casi in cui `using namespace` ha un uso corretto).
```cpp
#include <string>
#include <iostream>
`
int main() {
	using namespace std::string_literals; // per il suffisso s

	std::cout << "Ciao!\n"; // C-Style string literal
	std::cout << "Come va?\n"s; // std::string literal
	return 0;
}
```

Questa è una funzione che non servirà molto spesso, ma solo in specifici casi in cui è necessario **dedurre il tipo di un oggetto**.

#### `constexpr std::string`
Definire una `constexpr std::string` genererà, probabilmente, **errore di compilazione**. 
Questo perchè `std::string` non è completamente supportato nel linguaggio.

Se si ha la necessità di usare una `constexpr` per valutare una stringa a *compile-time*, utilizzare `std::string_view`.
