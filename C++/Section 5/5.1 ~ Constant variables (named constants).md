In programmazione, una ***costante*** è un valore che **potrebbe non cambiare** durante l'esecuzione di un dato programma.

C++ ammette due tipologie di costanti:
- Le **costanti con nome**, che sono costanti a cui è associato un identificatore;
- Le **costanti letterali** a cui invece non è associato un identificatore.
#### Tipi di *named constants*
Ci sono 3 modi per definire ***costanti con nome*** in C++:
- Tramite **variabili costanti**, che vedremo a breve;
- Tramite una macro `#define` del [[2.10 ~ Introduction to the preprocessor#Macro defines|preprocessore]];
- Tramite una **costante enumerativa**.

#### Constant Variables
Finora, tutte le variabili che abbiamo visto **sono non costanti**, ossia che il loro valore può cambiare in ogni momento.
```cpp
int main() {
	int x { 4 }; // x non è costante...
	x = 5; // ...infatti il suo valore cambia!
	
	return 0;
}
```
Tuttavia, ci sono molti casi in cui è utile definire delle costanti le quali tendono a non cambiare durante l'esecuzione. Definire delle costanti ci assicura che **questi valori non cambino durante l'esecuzione**, assieme ad altri vantaggi che vedremo in seguito.

#### Definire variabili costanti
Per dichiarare una variabile costante, si utilizza la *keyword* `const` (chiamata *const qualifier*) posta adiacente al tipo di dato dell'oggetto.
```cpp
// È preferibile apporre const prima del tipo.
const double gravity { 9.8 }; // Preferibile
int const squareSides { 4 };
```
La posizione di `const` è indifferente, ma è **good practice** porre la *keyword* prima del tipo di dato.
Si noti come il tipo di dato **contiene eventualmente il *const qualifier***. Nell'esempio fatto sopra, il tipo di dato `gravity` è `const double`.

#### Gli oggetti `const` vanno inizializati
Le variabili di tipo `const` vanno **necessariamente inizializzate quando vengono definite**, e il loro valore non può cambiare - in entrambi i casi si genererà un errore di compilazione.

È possibile definire delle variabili `const` a partire da altre variabili.

```cpp
#include <iostream>

int main() {
	std::cout << "Inserisci numero: ";
	int num {};
	std::cin >> num;
	
	// Costante iniializzata dalla variabile num
	const int constNum { num };
	
	num = 67; // OK: num non è var. costante
	constNum = 69; // ERRORE: num è var. costante

	return 0;
}
```

Per quanto riguarda la nomenclatura degli identificatori, si può usare la notazione di C, dove gli identificatori sono scritti **in maiuscolo con spazi separati da underscore** (`MY_CONST`), o in modo più moderno **in camelCase con l'identificatore che inizia con `k`** (`kMyConst`).

#### Parametri e valori di ritorno `const`
È possibile specificare parametri di funzione di tipo `const`;
questo fa in modo che, il parametro, all'interno della funzione, non cambi il proprio valore fino alla fine della sua esecuzione. Questo è diventato nel corso del tempo particolarmente inutile, in quanto il valore del parametro è una copia del valore inserito e viene in ogni caso distrutto al termine del suo scope. Pertanto è preferibile **non utilizzare `const` per parametri** di funzione.

Inoltre è anche possibile specificare, come tipo di dato di ritorno, un tipo `const`.  In questo caso `const` viene semplicemente ignorato nel caso di tipi fondamentali ed ha poco significato nel caso di altri tipi di dato. Anche in questo caso è preferibile **non utilizzare `const` per valori di ritorno**.

#### Perché le variabili vanno rese costanti
Se una variabile può essere resa costante, **è generalmente consigliabile porre `const` nella definizione**. Questo per una serie di motivi:
- Riduce le possibilità di bug evitando che il valore possa cambiare accidentalmente;
- Il compilatore ottimizza meglio le variabili di tipo `const`, assumendo di base che il valore non cambi;
- Riduce la complessità del programma, permettendo di escludere una variabile di tipo `const` dal debugging nel caso di un risultato diverso dal valore della costante.
***È buona pratica rendere le variabili `const` quando possibile.***

#### Variabili costanti vs. Macro
Abbiamo visto che, tramite la direttiva preprocessore `#define` è possibile definire delle *object-like* macro che sostituiscono testo con altro testo - questo rende possibile la definizione di costanti.

È preferibile dunque usare le *object-like* macro o le variabili di tipo `const`? La risposta è **la seconda tipologia**. Questo perché le macro **non seguono regole standard di *scoping***, generando a volte comportamenti inaspettati e rendendo eventuali bug difficili da debuggare; al contrario, le variabili costanti sono facili da debuggare in quanto visibili dal compilatore.

#### Variabili costanti in programmi multi-file
In molti casi è normale utilizzare delle stesse costanti in uno stesso programma, il quale è spesso formato da più file. Invece di definire ogni volta le costanti, è opportuno metterle in un luogo centrale accessibile da ogni file del codice quando necessario. In questo modo, oltre a definirle una sola volta, nel caso vadano apportate modifiche vanno apportate una sola volta.

#### Type Qualifiers
Un ***type qualifier*** è una *keyword* che viene applicata ad un **tipo di dato**, modificandone il comportamento.

`const` è un ***type qualifier*** (chiamato *const type qualifier*) utilizzato per dichiarare che il valore di una variabile non può cambiare nel corso dell'esecuzione.

I due *type qualifier* presenti in C++ **sono `const` e `volatile`** (usato per comunicare al compilatore che, in ogni momento, il valore della variabile può cambiare, utile per concorrenza). Nella documentazione tecnica questi due *type qualifiers* vengono detti **cv-qualifiers** e le variabili si dicono:
- ***cv-unqualified***: è una variabile che **non ha un type qualifier**.
- ***cv-qualified***: è una variabile che ha **uno o più type qualifiers**.
- ***possibly cv-qualified***: è una variabile che **potrebbe essere** *cv-qualified o cv-unqualified*.
