Abbiamo visto nella [[1.3 ~ Introduction to objects and variables|scorsa lezione]] come definire una [[1.3 ~ Introduction to objects and variables#Variables|variabile]] al fine di contenere [[1.3 ~ Introduction to objects and variables#Values|valori]]. Ora vediamo come assegnare gli effettivi valori ad una corrispettiva variabile. 

### Assegnazione di variabili
Dopo che una variabile è stata **definita**, è possibile ***attribuirle un valore*** tramite ***l'operatore di assegnazione*** `=`.
```cpp
int width; // Definisco la variabile width, di tipo int.
width = 5; // Assegno alla variabile width il valore 5

// A questo punto width contiene il valore 5
```
Di base, l'assegnazione **copia il valore posto a destra e lo assegna alla variabile che è a sinistra**. Questo tipo di assegnazione è chiamato ***copy-assignment***. Ogni volta che vogliamo cambiare il valore contenuto all'interno di una certa variabile basterà utilizzare nuovamente l'operatore di assegnazione `=`.
```cpp
int main() {
	int width;
	
	width = 5; // width contiene 5
	std::cout << width; // Verrà stampato 5
	
	width = 7; // width contiene ora 7
	std::cout << width; // Verrà stampato 7

	return 0;
}
// Output finale: 57
```

### Inizializzazione di variabili
La parte negativa dell'assegnazione è che per attribuire un valore ad una variabile sono necessarie due operazioni: una di definizione della variabile ed una di assegnazione del valore. Questi due passaggi possono essere ***opzionalmente combinati***, permettendo di definire una variabile **avente già un valore iniziale**. Questo passaggio prende il nome di ***initialization*** (inizializzazione) e la sintassi usata per effettuarla prende il nome di ***initializer***.
```cpp
#include <iostream>

int main() {
	int width { 5 }; // width viene definita con un valore iniziale di 5
	std::cout << width; // Stampa 5.
	
	return 0;
}
```
Nell'esempio sopra `width` è la variabile definita, `{ 5 }` è l'***initializer*** e `5` è **il valore iniziale**.

### Forme di inizializzazione
A differenza dell'assegnazione, per cui basta utilizzare l'operatore di assegnazione `=`, è possibile effettuare l'inizializzazione in diversi modi, ciascuno avente le sue peculiarità.

#### Default-initialization
La ***default-initialization*** avviene se, dopo la definizione di una variabile, non si utilizza un *initializer*. In questo caso non viene assegnato direttamente un valore iniziale a tale variabile, lasciandola pertanto con un ***valore indefinito*** (spesso chiamato *garbage value*).
```cpp
int a; // Default-initialization - a avrà un valore iniziale indefinito.
```

#### Copy-initialization
La ***copy-initialization*** è stata ereditata dal linguaggio C. Il valore iniziale viene fornito dopo l'operatore di assegnazione `=`.
```cpp
int a = 5; // Copy-initialization - a avrà il valore iniziale 5.
```
Questa inizializzazione, in modo uguale al ***copy-assignment*** copia il valore presente sulla destra dell'operatore e lo inserisce nella variabile presente alla sua sinistra.

Questo tipo di inizializzazione è caduto in disuso in favore di inizializzazioni più efficienti introdotte dal C++, nonostante con gli aggiornamenti può venire ancora utilizzata.

#### Direct-initialization
Nella ***direct-initialization*** il valore iniziale viene fornito tra **parentesi tonde** `( )`.
```cpp
int a ( 5 ); // Direct-initialization - a avrà il valore iniziale 5.
```
Questo tipo di inizializzazione è stata introdotta per avere una forma di inizializzazione più efficiente di **oggetti complessi**. Anche questa tipologia è caduta in disuso a causa di forme di inizializzazione più efficienti introdotte dal C++.

#### List-initialization
Nella ***list-initialization*** il valore iniziale viene fornito tra **parentesi graffe** `{ }`. Questo tipo di inizializzazione può essere realizzato con o senza l'operatore di assegnazione `=` - se viene utilizzato si parla di ***copy-list-initialization*** (meno usata), altrimenti si parla di ***direct-list-initialization*** (la più usata in assoluto).
```cpp
int width { 5 }; // direct-list-initialization: width avrà valore iniziale 5
int height = {6}; // copy-list-initialization: height avrà valore iniziale 6
```
Prima dell'introduzione di questo tipo di inizializzazione si aveva difficoltà a capire quale tipologia di inizializzazione utilizzare: in certi casi si usava la *direct-initialization* e in altri la *copy-initialization*. Questo tipo di inizializzazione ***uniforma tutti gli altri tipi di inizializzazione*** che funziona in quasi ogni caso e non ha una sintassi ambigua, permettendo di capire subito quando stiamo inizializzando un oggetto.
Inoltre questo tipo di inizializzazione permette di inizializzare oggetti che permettono di contenere una lista di valori e non un valore singolo (proprio per questo si chiama *list-initialization*).

##### La list-initialization non permette narrowing
La *list-initialization* non permette ciò che viene chiamata una ***narrowing conversion*** ossia la conversione da un tipo di dato ad un altro con perdita di dati. 
Un esempio tipico è l'inizializzazione di un `int` con un valore con virgola mobile - tale valore va convertito in un intero, perdendo quindi la parte decimale. 
Se si utilizza *list-initialization* queste conversioni non sono possibili, e se si prova ad utilizzarle il compilatore restituirà un errore di compilazione - tuttavia nelle altre inizializzazioni questo non causa un problema, e nemmeno tramite assegnazione. 
```cpp
int c { 4.5 }; 
// Errore di compilazione - narrowing conversion rilevata. (list-initialization)

int d = 4.5; // OK - d conterrà 4 (copy-initialization)
int l (4.5); // OK - l conterrà 4 (direct-initialization)

int a { 4 }; // OK - a conterrà 4 (list-initialization)
a = 7.5; // OK - a conterrà 7 (copy-assignement con narrowing da double a int).
```

#### Value-initialization e zero-initialization
Se si utilizza la ***list-initialization*** senza specificare un valore all'interno delle parentesi si parla di ***value-initialization***, un tipo speciale di *list-initialization*. Questa inizializzazione permette agli oggetti di venire inizializzati ***al loro valore di default***. Per la maggior parte degli oggetti questo valore è **0** - in questi casi si parla di ***zero-initialization***.
```cpp
int a {}; 
// a conterrà 0 come valore iniziale (value-initialization/zero-initialization)
```

***La forma di inizializzazione principale in C++ è la list-initialization (e di conseguenza anche value-initialization)*** poiché:
- Funziona nella maggior parte dei casi;
- Disabilita, per sicurezza, le *narrowing conversion*;
- Supporta l'inizializzazione di oggetti più complessi per mezzo di una lista di valori.

Quando si vuole inizializzare una variabile al suo valore di default (ad esempio inizializzare un `int` a 0) si utilizza:
- Direct-list-initialization se la variabile viene usata subito dopo essere inizializzata:
```cpp
int a { 0 }; // direct-list-initialization
std::cout << a; // uso subito il valore
```
- Value-initialization se il valore contenuto dentro la variabile viene rimpiazzato:
```cpp
int a {}; // value-initialization
std::cin >> a; // rimpiazzo subito il valore presente in a
```

> [!tip] È buona pratica ***inizializzare sempre le variabili***, al fine di evitare di avere variabili con valori indefiniti.

### Instantation
Con il termine ***instantation*** (instanziamento) si riferisce alla pratica per indicare **la definizione e l'inizializzazione di una variabile** (anche usando *default-initialization*). Una variabile definita e inizializzata prende anche il nome di **istanza**.

### Inizializzazione multipla di variabili
Abbiamo visto come [[1.3 ~ Introduction to objects and variables#Definizione multipla di variabili|definire multiple variabili sulla stessa riga]]. È possibile anche **inizializzare multiple variabili sulla stessa riga**.
```cpp
int a = 5, b = 6; // Copy-initialization
int c ( 7 ), d ( 8 ); // Direct-initialization
int e { 9 }, f { 10 }; // Direct-list-initialization
int g {}, h {}; // Value-initialization
```
È necessario ricordarsi che **ogni variabile deve possedere il proprio *initializer*** o altrimenti conterrà un valore non definito.
```cpp
int a, b = 5; // a non è inizializzata, b invece è inizializzata col valore 5.
int a = 4, b = 5; // a e b sono inizializzate coi valori 4 e 5 rispettivamente.
```

### Variabili non usate
Se una variabile viene istanziata, ma non utilizzata, il compilatore segnalerà per mezzo di un ***warning*** il fatto che tale variabile non è stata utilizzata.
```cpp
#include <iostream>

int main() {
	int x { 5 }; // Variabile x istanziata.
	// Però non uso x!
	return 0;
}
// Il compilatore segnalerà con un warning il mancato uso di x. 
```
Per ovviare a questo problema ci sono due alternative:
- Utilizzare la variabile istanziata da qualche parte nel codice;
- Eliminare la variabile se effettivamente non viene utilizzata;
- Utilizzare, prima dell'istruzione di definizione della variabile, l'attributo `[[maybe_unused]]`, il quale segnala al compilatore che se tale variabile non viene usata nel codice non deve segnalare il suo mancato utilizzo.
```cpp
#include <iostream>

int main() {
	[[maybe_unused]] double pi { 3.141 };
	[[maybe_unused]] double g { 9.81 };
	double radius { 3.5 };
	
	std::cout << "La circonferenza vale: " << pi * 2 * radius;
	return 0;
}
// g non è stata utilizzata, ma il compilatore non mi darà un warning poiché è presente [[maybe_unused]] prima della sua definizione.
```
