### Commenti
Un ***commento*** è una **nota**, leggibile da chi possiede il codice, inserita direttamente nel codice sorgente. I commenti ***vengono ignorati dal compilatore*** e sono solamente ad uso del programmatore. Questi possono essere usati per indicare cosa producono i blocchi di codice scritti e spesso usati per evitare incomprensioni. 

È possibile scrivere commenti in due modi diversi:
Tramite **doppio slash** `//`, usato per i commenti a singola riga:
```cpp
std::cout << "Hello World!"; // Ciao! Sono un commento a singola riga.
```
I quali possono anche essere allineati per mezzo di *tab-stops*:
```cpp
std::cout << "It is very nice to meet you!\n"; // this is much easier to read
std::cout << "Yeah!\n";                        // don't you think so?
```
o semplicemente facendo spazio tra le righe:
```cpp
// std::cout lives in the iostream library
std::cout << "Hello world!\n";

// this is much easier to read
std::cout << "It is very nice to meet you!\n";

// don't you think so?
std::cout << "Yeah!\n";
```

Tramite **le coppie di simboli `/*` e `*/`**, usati per commenti a riga multipla:
```cpp
/* Questo è
   un commento
   multi-linea! */
```
Questi non possono essere innestati:
```cpp
/* This is a multi-line /* comment */ this is not inside the comment */
// The above comment ends at the first */, not the second */
```
Ma possono essere resi "più belli" nel seguente modo:
```cpp
/* This is a multi-line comment.
 * the matching asterisks to the left
 * can make this easier to read
 */
```

I commenti **non devono essere abusati**, ossia che:
- Vanno usati per indicare ***parti di codice ambigue, che vanno dunque opportunamente documentate***, oppure per indicare **strategie adottate durante la programmazione**.
- Non vanno usati invece per indicare parti di codice **ovvie** o per **creare ancor più ambiguità**.
