#### Introduzione alla conversione implicita di tipo
Consideriamo il seguente programma:
```cpp
#include <iostream>

void printValue(double x) {
	std::cout << "Valore stampato: " << x << '\n';
}

int main() {
	printValue(5); // passo un int al posto di un double
	
	return 0;
}
```
La funzione `printValue()` accetta come parametro un valore `double`, ma, quando viene chiamata all'interno di `main()`, viene passato un valore **intero** - come si comporta quindi la funzione?

Nella maggior parte dei casi, C++ **converte in automatico un tipo di dato fondamentale in un altro** - questo processo prende il nome di ***type conversion***. Nell'esempio appena fatto, l'intero `5` passato come argomento verrà convertito in un `double` che ha valore `5.0` e poi copiato dentro il parametro `x`.  Il codice avrà quindi come output `5`.

Quando il compilatore effettua una conversione di tipo senza che questa venga richiesta in modo esplicito, tale conversione viene detta ***implicita***. L'esempio appena fatto mostra una conversione implicita - alla chiamata di funzione non abbiamo richiesto la conversione da un `int` a un `double`, ma è avvenuta automaticamente. 

#### La conversione di tipo di un valore produce un nuovo valore
Supponiamo di avere il seguente programma:
```cpp
#include <iostream>

void printValue(double x) {
	std::cout << "Valore stampato: " << x << '\n';
}

int main() {
	int y { 5 };
	printValue(y); // y è di tipo int
\	
	return 0;
}
```
Quando avviene la conversione di tipo da `int` a `double`, la variabile `y` ***non viene modificata***, ossia che il suo tipo di dato **non cambia dopo la conversione**. Infatti il processo di conversione **usa come input il valore iniziale** e produce come output **un nuovo oggetto del tipo di dato convertito** relativo al valore iniziale inserito. 
*La conversione, pertanto, funziona in modo simile alle funzioni, in cui il valore di ritorno è inserito in un oggetto temporaneo e poi copiato al posto della chiamata*.

#### Warning relativi a conversioni di tipo implicite
Supponiamo ora di avere il seguente codice:
```cpp
#include <iostream>

void printValue(int x) {
	std::cout << "Valore stampato: " << x << '\n';
}

int main() {
	double y { 5.5 };
	printValue(y); // y è di tipo double
	
	return 0;
}
```
A differenza degli esempi precedenti, in cui la conversione avveniva da un `int` a un `double`, qui abbiamo una conversione da `double` a `int`. Quando proviamo a compilare questo codice, il nostro compliatore ci restituirà un ***warning*** legato a una **possibile perdita di dati**.

Questo è dovuto al fatto che gli `int` non possono mantenere numeri aventi componenti frazionarie - pertanto quando un `double` viene convertito ad `int`, la parte frazionaria viene rimossa (qui avviene la segnalata perdita di dati), mantenendo solo quella intera. 

#### Introduzione alla conversione esplicita tramite `static_cast`
Supponiamo, nell'ultimo esempio, di voler **volontariamente** passare un valore di tipo `double` alla funzione `printValue()` che accetta parametri di tipo `int`.

Come abbiamo visto, se la conversione avviene in modo implicito otterremo un ***warning*** riguardante alla perdita di dati. Al fine di rendere compilabile il codice, avremmo bisogno di disabilitare l'opzione *"treat warnings as errors"* - tuttavia questo mostrerà, ad ogni compilazione, il *warning* e rischiamo di non vedere problemi ben più importanti.

C++ supporta **un altro tipo di conversione**, detta ***esplicita***. Quando effettuiamo una **conversione di tipo esplicita**, il programmatore **richiede esplicitamente al compilatore** di effettuare la conversione di un tipo in un altro - questo non genererà warning in quanto **la responsabilità sull'eventuale perdita di dati è, in questo caso, del programmatore che ha richiesto la conversione**.

Per effettuare una conversione esplicita si fa uso **dell'operatore `static_cast`**. La sintassi di questo operatore è:
```cpp
static_cast<new_type>(expression)
```
`static_cast` prende come input una espressione `expression`, il cui risultato viene poi convertito nel tipo di dato richiesto `new_type` e poi restituito come output.

Utilizzando nell'ultimo esempio fatto `static_cast`:
```cpp
#include <iostream>

void printValue(int x) {
	std::cout << "Valore stampato: " << x << '\n';
}

int main() {
	double y { 5.5 };
	// y viene convertito a int e il nuovo valore prodotto
	// da static_cast viene passato come parametro
	printValue( static_cast<int>(y) );
	
	return 0;
}
```
Siccome ora stiamo richiedendo esplicitamente la conversione del `double` `y` in un `int`, non verrà generato nessun *warning*.

#### Usare `static_cast` per convertire `char` a `int`
Abbiamo visto [[4.11 ~ Chars#`char` e caratteri|nella lezione relativa ai caratteri]] che, essendo ***integrals***, i `char` vengono memorizzati come numeri interi e tali numeri vengono interpretati come il carattere ASCII corrispondente al numero memorizzato.

È possibile, tramite `static_cast`, effettuare la conversione di un `char` a `int` - in particolare la conversione restituirà **il codice ASCII corrispondente al carattere inserito**.
```cpp
#include <iostream>

int main() {
	char myChar { 'a' };
	std::cout << myChar << " ha valore ASCII " 
		<< static_cast<int>(myChar) << '\n';
		
	return 0; 
}
```
Output:
```
a ha valore ASCII 97
```

#### Conversione tra *signed* e *unsigned*
È possibile convertire `signed`a `unsigned` e viceversa, usando `static_cast`.
- Se il valore di partenza **può essere rappresentato nel nuovo tipo**, il valore risultante alla conversione **sarà lo stesso di partenza con il tipo convertito** (per esempio se il valore è positivo e nel range positivo di un `signed`)
- Se il valore di partenza **non può essere rappresentato nel nuovo tipo**, allora il comportamento cambia dal tipo di arrivo:
	- Se il tipo di arrivo è `unsigned`, allora il valore iniziale viene *wrappato* in modulo $2^n$, come visto in [[4.5 ~ Unsigned integers, and why to avoid them#Unsigned integer overflow|questa lezione]].
	- Se il tipo di arrivo è `signed`, allora il comportamento è **determinato dal compilatore**, oppure viene *wrappato* in modulo $2^n$ (da C++20 in poi).

##### Gli *integers* a dimensione fissa di 8 bit si comportano come `char`
Come abbiamo visto [[4.6 ~ Fixed-width integers and size_t#Perchè `std int8_t` e `std uint8_t` si comportano come `char`|qui]], gli integer della tipologia `std::int8_t` e `std::uint8_t` (e le loro varianti *least* e *fast*) vengono trattate dalla maggior parte dei compilatori come `signed char` e `unsigned char`. 

```cpp
#include <cstdint>
#include <iostream>

int main() {
    std::int8_t myInt{65};      // myInt ha valore iniziale 65
    std::cout << myInt << '\n'; // dovrebbe stampare 65
	
    return 0;
}
```
Quando andiamo ad eseguire il programma, su alcune macchine verrà restituito `65`, ma su altre verrà stampato il carattere `A`.  Se vogliamo garantire che in output venga sempre stampato il valore effettivo, bisognerà effettuare uno `static_cast` a `int` della variabile. 
```cpp
#include <cstdint>
#include <iostream>

int main() {
    std::int8_t myInt{65};      // myInt ha valore iniziale 65
    std::cout << static_cast<int>(myInt) << '\n'; // garantita la stampa 65
	
    return 0;
}
```
I problemi non solo si manifestano in output, ma anche in **input**: all'inserimento di valori in uno di questi tipi di dato per mezzo di `std::cin`, ciò che viene estratto viene trattato come ***carattere*** e non come intero.
```cpp
#include <cstdint>
#include <iostream>

int main() {
    std::cout << "Inserisci un numero tra 0 e 127: ";
    std::int8_t myInt{};
    std::cin >> myInt;

    std::cout << "Hai inserito: " << static_cast<int>(myInt) << '\n';

    return 0;
}
```
Se inseriamo `35`:
```
Inserisci un numero tra 0 e 127: 35
Hai inserito: 51
```
Questo accade per il seguente motivo:
- `std::int8_t` viene interpretato come `char`, quindi ciò che viene inserito in input verrà estratto da `std::cin` come ***carattere***
- Inserendo `35` abbiamo inserito i caratteri `'3'` e  `'5'`. Il carattere `'3'` viene inserito in `myInt`, mentre il carattere `'5'` rimane nel buffer di `std::cin`.
- Alla stampa del valore, verrà stampato il codice ASCII del valore contenuto in `myInt`. In questo caso in `myInt` è memorizzato `'3'`, il cui corrispondente codice ASCII è `51`.
