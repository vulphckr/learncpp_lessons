#### Grandezze degli oggetti
Come abbiamo visto [[4.1 ~ Introduction to fundamental data types|durante l'introduzione]], ad ogni variabile viene riservato un indirizzo di memoria, in cui all'interno è presente il valore contenuto all'interno di essa. Abbiamo anche visto come ogni indirizzo di memoria contenga esattamente **un byte**. 

Ebbene, non tutti gli oggetti possono essere rappresentati per mezzo di un singolo byte. Un oggetto può far uso di 1, 2, 4, 8 o più byte consecutivi e di altrettanti indirizzi di memoria consecutivi. **Il numero di byte utilizzati da un oggetto dipende dal suo tipo di dato**.

Il compilatore conosce già quanti byte vengono utilizzati per una variabile di un certo tipo, e il processo avviene automaticamente; tuttavia è importante conoscere quanta memoria occupa un certo oggetto.

**Maggiore è la memoria che occupa un oggetto, maggiore è la quantità di informazioni che può memorizzare**. Un oggetto che occupa $n$ bit può contenere $2^n$ valori differenti. Questo significa che ogni tipo di dato ha un numero massimo di valori che esso può rappresentare - questo può essere importante in certi casi, come per esempio per i numeri interi.

Inoltre, **i calcolatori hanno un numero finito di memoria disponibile**. Ogni volta che viene allocato un oggetto, parte di quella memoria disponibile viene riservata a quell'oggetto e di fatto smette di essere disponibile per altre. Siccome i calcolatori moderni hanno tanta memoria, l'impatto non è significativo - ma per programmi che hanno bisogno di molti oggetti (ordine dei milioni) ciò potrebbe risultare significativo. È bene però effettuare ottimizzazioni di spazio su qualcosa di già funzionante, invece che puntare sin da subito a effettuare un programma efficiente (sempre meglio mantenere che rendere efficiente).

#### Operatore `sizeof()`
Per capire, su una certa macchina, quanto occupa un determinato tipo di dato, è possibile usare l'operatore unario `sizeof()`. L'operatore accoglie come unico parametro **un tipo di dato**, e **restituisce il numero di byte che tale tipo di dato occupa**.

Questo programma restituisce, per ogni tipo di dato fondamentale, quanto esso occupa:
```cpp
#include <iomanip> // for std::setw (which sets the width of the subsequent output)
#include <iostream>
#include <climits> // for CHAR_BIT

int main()
{
    std::cout << "A byte is " << CHAR_BIT << " bits\n\n";

    std::cout << std::left; // left justify output

    std::cout << std::setw(16) << "bool:" << sizeof(bool) << " bytes\n";
    std::cout << std::setw(16) << "char:" << sizeof(char) << " bytes\n";
    std::cout << std::setw(16) << "short:" << sizeof(short) << " bytes\n";
    std::cout << std::setw(16) << "int:" << sizeof(int) << " bytes\n";
    std::cout << std::setw(16) << "long:" << sizeof(long) << " bytes\n";
    std::cout << std::setw(16) << "long long:" << sizeof(long long) << " bytes\n";
    std::cout << std::setw(16) << "float:" << sizeof(float) << " bytes\n";
    std::cout << std::setw(16) << "double:" << sizeof(double) << " bytes\n";
    std::cout << std::setw(16) << "long double:" << sizeof(long double) << " bytes\n";

    return 0;
}
```
Che sul mio PC restituisce:
```
A byte is 8 bits

bool:           1 bytes
char:           1 bytes
short:          2 bytes
int:            4 bytes
long:           8 bytes
long long:      8 bytes
float:          4 bytes
double:         8 bytes
long double:    16 bytes
```
Ma il risultato può cambiare sulla base del compilatore, dell'architettura del processore, del sistema operativo...

È anche possibile specificare come parametro una variabile. Verrà in quel caso restituito **quanto occupa il tipo di dato di quella variabile** (e di fatto quanto occupa quella variabile).
Utilizzare `sizeof()` su un [[4.2 ~ Void#Tipi di dato incompleto|tipo di dato incompleto]] risulterà in un errore di compilazione.

##### Performance dei tipi di dato fondamentali
I tipi di dato fondamentali sono molto efficienti su macchine moderne. Non è generalmente necessario fare attenzione alle performance.
