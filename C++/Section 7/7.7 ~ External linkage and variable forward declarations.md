Nella [[7.6 ~ Internal linkage|scorsa lezione]] abbiamo parlato di ***internal linkage***, il quale limita **la visibilità di un identificatore ad un singolo file**. In questa lezione parleremo invece di ***external linkage***.

Un identificatore avente ***external linkage*** **può essere visto e utilizzato *sia nel file in cui viene definito* sia *da altri file***. In questo senso, gli identificatori che hanno *external linkage* ***sono globali nel vero senso della parola***: possono essere utilizzati **in ogni punto del programma**.

Gli identificatori che hanno ***external linkage*** sono ***visibili al linker***. Ciò significa che quest'ultimo può eseguirvi due cose:
- **Connettere** un identificatore usato in una *translation unit* alla **sua definizione**, posta in *un'altra translation unit*;
- **Non permettere la duplicazione di identificatori *inline***, in modo che rimanga solo una definizione canonica. *Questo verrà visto in seguito*.

#### Le funzioni hanno *external linkage* di default
Nella lezione legata [[2.8 ~ Programs with multiple files|ai programmi con più file]] abbiamo visto che è possibile chiamare una funzione **che è stata definita in un altro file**. Questo è possibile grazie al fatto che le funzioni ***di default hanno external linkage***.

Al fine di poter richiamare una funzione che è stata definita all'interno di un altro file, è necessario porre, nei file in cui si vuole effettuare la chiamata, ***una forward declaration*** a tale funzione. In questo modo verrà comunicato al compilatore ***l'esistenza di tale funzione in un altro file***, al fine di permetterne il corretto linking.

Vediamo un esempio:
`a.cpp`
```cpp
#include <iostream>
// Funzione - possiede external linkage di default

void sayHello() {
	std::cout << "Hello!\n"; 
}
```
`main.cpp`
```cpp
#include <iostream>

// Forward declaration per sayHello()
// In questo modo la funzione è
// accessibile in questo file
void sayHello();

int main() {
	// Il linking avviene correttamente
	sayHello();
	return 0;
}
```
Output: `Hello!`
In questo caso, `sayHello()` viene definita all'interno di `a.cpp`, e possiede ***external linkage***, ossia è visibile dagli altri file. `main.cpp` possiede una ***forward declaration*** per `sayHello()`, la quale permette al linker di *linkare* tale identificatore alla definizione posta in `a.cpp`. Il programma **compila e funziona senza problemi**, ma se ci fossero stati problemi di *linking* tra definizione e identificatore, si sarebbe generato un errore di compilazione o linker.

#### Variabili globali con *external linkage*
Le variabili globali che possiedono **external linkage** sono anche dette ***external variables***. Per *esternare una variabile globale* è possibile usare la keyword `extern`. 

Le variabili globali ***non costanti*** hanno ***external linkage di default***, pertanto la keyword `extern` non è necessaria.

#### Forward declarations di variabili tramite `extern`
Per fare in modo di utilizzare una ***external variable*** definita in un altro file, è necessario porre ***una forward declaration*** per la variabile globale **in altri file in cui si vuole usare tale variabile**. Creare una *forward declaration* per una variabile necessita l'uso della keyword `extern`.

Vediamo con un esempio:
`main.cpp`:
```cpp
#include <iostream>

// Queste sono forward declaration per
// variabili che sono definite altrove
extern int g_x;
extern const int g_y;

int main() {
	std::cout << g_x << " " << g_y << '\n';
	
	return 0;
}
```
`a.cpp`
```cpp
// Definizioni delle variabili locali
int g_x { 2 }; // Non costante - default external linkage
extern const int g_y { 3 }; // Uso di extern per external linkage
```
In questo esempio, sia `a.cpp` che `main.cpp` fanno riferimento alle stesse variabili `g_x` e `g_y`, le cui definizioni sono all'interno di `a.cpp`. `main.cpp` può comunque utilizzare queste variabili in quanto possiede ***le forward declarations*** di entrambe, ed esse faranno comunque riferimento agli oggetti definiti dentro `a.cpp`.

La keyword `extern` ha **significati diversi sulla base di dove si trova**:
- Nel caso di `a.cpp`, `extern` significa "questa variabile che definisco ha ***external linkage***":
- Nel caso di `main.cpp`, `extern` significa "questa è una forward declaration di una variabile definita da qualche altra parte".

Le ***forward declaration*** di funzioni non hanno la necessità di usare la keyword `extern`, in quanto il compilatore è in grado di differenziare la definizione da una *forward declaration* (sulla presenza o meno del corpo di funzione). Tuttavia, le *forward declaration* di variabili ***sono necessarie***, altrimenti sembrano identiche.
```cpp
// non costanti
int g_x; // Definizione senza inizializzazione
int g_x { 1 }; // Definizione con inizializzazione
extern int g_x; // Forward declaration

// costanti
extern const int g_y { 1 }; // Definizione di variabile
extern const int g_y; // Forward declaration
```

#### Evitare l'uso di `extern` per variabili *non costanti* inizializzate
Le seguenti due linee sono equivalenti:
```cpp
int g_x { 1 }; // Extern di default
extern int g_x { 1 }; // Specifico extern
```
Il compilatore può **generare un warning per la seconda istruzione**, anche se è valida sintatticamente.
Questo perché l'uso di `extern` viene considerato ***sospetto dal compilatore***, in quanto non riesce con certezza a definire se tale istruzione è una ***forward declaration*** (a causa della presenza dell'inizializzatore) oppure una ***definizione*** (a causa della keyword `extern`) - per rimuovere il warning, è necessario rimuovere la keyword o l'identificatore, in modo da rendere chiaro l'uso di questa variabile. 

La ***best practice*** è quella di usare `extern` **solo nel caso di variabili globali costanti e `constexpr`**.

#### Sommario sull'***external linking***
```cpp
// Forward declaration
extern int g_y; // non-const
extern const int g_y; // const
extern constexpr int g_y; // constexpr

// Definizioni (variabili non costanti) - non usano extern
int g_x; // External linkage di default
int g_x { 1 }; // Con inizializzazione

// Definizioni (variabili costanti) - usano extern
extern const int g_x { 2 }; // const
extern constexpr int g_x { 3 }; // constexpr
```
