Nella [[7.3 ~ Local Variables|lezione precedente]] abbiamo visto le **variabili locali** - variabili definite all'interno di blocchi (solitamente *all'interno di corpi di funzione*). 
Le variabili locali:
- hanno ***block scope***, ossia che *sono in scope* dal punto della loro definizione fino al termine del blocco in cui sono contenute 
- hanno ***automatic storage duration***, ossia che sono *create* nel momento in cui vengono definite e distrutte nel momento in cui *vanno out of scope*.
- **non hanno *linkage*.

Se una variabile viene dichiarata **fuori da qualsiasi blocco** (e quindi fuori da qualsiasi funzione) essa viene detta ***global variable*** (*variabile globale*).

#### Dichiarazione di variabili globali
Una variable globale, per convenzione, viene inserita ***in cima al file, sotto alle direttive preprocessore*** e nel ***[[2.9 ~ Naming collisions and an introduction to namespaces#Il Global Namespace|global namespace]]***.
```cpp
#include <iostream>

int global_var {}; // variabile globale

void doSomething() {
	// Chiunque, nel file, può accedere alle variabili globali
	global_var = 3;
	std::cout << global_var << '\n';
}

int main() {
	doSomething();
	global_var++;
	
	std::cout << global_var << '\n';
	return 0;
}
// global_var va out of scope QUI
```
Output:
```
3
4
```

#### Lo *scope* delle variabili globali
Identificatori dichiarati nel *global namespace* hanno ***global namespace scope***, ossia che *sono in scope* **dal momento della loro definizione fino *alla fine del file***.

Una volta dichiarate, le variabili globali ***sono accessibili da ogni punto del file***. Nell'esempio fatto prima, sia `main()` che `doSomething()` modificano e operano con la variabile globale `global_var`.

Le variabili globali **possono (*ed è best practice*) essere definite anche all'interno di [[7.2 ~ User-defined namespaces and the scope resolution operator|user-defined namespaces]]** - anche se l'identificatore è limitato dallo scope del namespace, esso ***è comunque accessibile globalmente tramite `operator::`***.

#### Le variabili globali hanno *static storage duration*
Le variabili globali ***vengono create all'avvio del programma, prima dell'esecuzione di `main()`*** e vengono ***distrutte al termine della sua esecuzione***. Questo tipo di *storage duration* è detta ***static duration***.

Variabili con ***static duration*** vengono spesso chiamate ***static variables***.

#### Nomenclatura delle variabili globali
Per convenzione, il nome delle variabili globali deve iniziare con il prefisso `g_`; questo per vari motivi:
- Evita conflitti con altri identificatori nel *global namespace*;
- Rende più difficile da causare il *variable shadowing*;
- Indica che tale variabile, quando usata, ha scope globale e quindi non andrà *out of scope* al termine del blocco in cui viene usata.

Se una variabile globale viene inserita all'interno di un namespace utente *il prefisso può essere escluso*. 

#### Inizializzazione delle variabili globali
A differenza delle variabili locali, le quali di default *non sono inizializzate*, ***le variabili globali sono zero-initialized***, ossia inizializzate a `0`.
Le variabili globali possono essere inizializzate a piacere.
```cpp
int g_x;       // Default-Initialization - inizializzata a 0
int g_y {};    // Value-Initialization - inizializzata a 0
int g_z { 3 }; // Direct-List-Initialization - inizializzata a 3
```

#### Variabili costanti globali
In modo uguale alle variabili locali ***anche le variabili globali possono essere costanti***, di tipo `const` o `constexpr`. Come richiesto da questi ultimi tipi di dato, ***essi devono essere inizializzati***, ossia ***non permettono inizializzazione di default***, pena *errore di compilazione*.
```cpp
const int g_x;     // errore: una variabile costante va inizializzata
constexpr int g_w; // error: una variabile constexpr va inizializzata

const int g_y { 1 };     // variabile costante inizializzata a 1
constexpr int g_z { 2 }; // variabile constexpr inizializzata a 2
```

#### L'uso di variabili globali *non costanti* è scoraggiato
Seppur potrebbe sembrare comodo il fatto di non dover avere a che fare con gli *scope* una volta dichiarata una variabile globale, oppure per il fatto che esse non debbano essere passate a una funzione, **l'uso di variabili globali**, ***nel caso in cui non fossero costanti*** è **fortemente scoraggiato**. Vedremo il motivo in una prossima lezione.
