Nella lezione [[2.9 ~ Naming collisions and an introduction to namespaces]] abbiamo introdotto i concetti di ***naming collision*** e di ***namespaces***. Per rinfrescarci la memoria rispieghiamo brevemente entrambi i concetti.

Una ***naming collision*** avviene quando, nello stesso *scope*, esistono ***due definizioni per lo stesso identificatore***. In questo caso, il compilatore o il linker non sanno distinguere quale delle due definizioni sia quella corretta da usare. Vediamo un esempio di *naming collision*: supponiamo di avere questi tre files.
`foo.cpp`
```cpp
int doSomething(int x, int y) {
	return x + y;
}
```
`bar.cpp`
```cpp
int doSomething(int x, int y) {
	return x - y;
}
```
`main.cpp`
```cpp
#include <iostream>

int doSomething(int x, int y); // forward declaration

int main() {
	// Quale delle due eseguo?
	std::cout << doSomething(3, 4) << '\n';
	
	return 0;
}
```
Se il progetto contiene solo uno tra `foo.cpp` e `bar.cpp`, il codice compilerà con successo e all'esecuzione di `doSomething()` verrà usata la definizione del file che viene utilizzato. Tuttavia, se **entrambi i file** sono presenti nel progetto, si avrà una ***naming collision*** dovuta al fatto che nello *scope globale* si hanno entrambe le definizioni. Il risultato è un ***errore di compilazione***:
```
bar.cpp:4: multiple definition of `doSomething(int, int)'; foo.cpp:4: first defined here
```
Notiamo che non è tanto un problema di quale `doSomething()` viene *chiamata*, poichè essendo un errore di compilazione ne riguarda **la definizione**.

Un modo per risolvere questo problema è quello di **modificare il nome della funzione** in uno dei due file, tuttavia questo significherebbe riscrivere tutte le chiamate a quella funzione al fine di richiamare quella corretta, e ciò potrebbe risultare lungo e prono a errori. L'altro modo, più supportato e ottimale, è quello di inserire le funzioni all'interno di un ***namespace***. Anche per questo motivo tutte le funzioni facenti parte della libreria standard sono state inserite nel namespace `std`.

#### Definire i *namespace*
C++ permette la *definizione* di *namespaces* utente tramite la *keyword* `namespace`. I *namespace* che vengono creati all'interno di programmi scritti dall'utente vengono detti ***user-defined namespaces***. La sintassi per la definizione è la seguente:
```cpp
namespace Identifier {
	// contenuto
}
```
Storicamente, l'identificatore del namespace *non ha la maiuscola iniziale* - ma la programmazione ad oggetti legati a una serie di scelte stilistiche **preferiscono l'uso di un nome avente la maiuscola iniziale**.

Un *namespace* può essere definito **dentro il *global scope* oppure *dentro ad un altro namespace***. In modo simile alle funzioni, il contenuto di un *namespace* viene indentato di un livello. Un `;` può essere posto dopo la definizione di un *namespace* (anche se non obbligatorio).

Riscriviamo l'esempio di *naming collision* fatto prima tramite l'uso di *namespaces*:
`foo.cpp`
```cpp
namespace Foo {
	int doSomething(int x, int y) {
		return x + y;
	}
}
```
`bar.cpp`
```cpp
namespace Bar {
	int doSomething(int x, int y) {
		return x - y;
	}
}
```
Adesso abbiamo `doSomething()` definita in due modi diversi, ma in *due namespace diversi*.
`main.cpp`
```cpp
#include <iostream>

int doSomething(int x, int y); // forward declaration

int main() {
	// Quale delle due eseguo?
	std::cout << doSomething(3, 4) << '\n';
	
	return 0;
}
```
Questa volta, otteniamo ***un altro errore***, in particolare di ***linker***.
```
ConsoleApplication1.obj : error LNK2019: unresolved external symbol "int __cdecl doSomething(int,int)" (?doSomething@@YAHHH@Z) referenced in function _main
```
Questo errore ci comunica che **il compilatore è soddisfatto** (*la forward declaration ha trovato le due definizioni di `doSomething()`*), tuttavia **il linker non riesce a trovare una definizione di `doSomething()` nel *namespace globale***. Questo perché *nessuna delle due definizioni è nel namespace globale*, ma ciascuna si trova all'interno del proprio ***scope del namespace***.

A questo punto, dobbiamo comunicare al compilatore quale delle due `doSomething()` vogliamo usare. Questo può essere fatto in due modi diversi:
- Tramite lo ***scope resolution operator***, `operator::`
- Tramite uno `using` statement.

#### Accedere a un *namespace* tramite `namespace::`
Il miglior modo per comunicare al compilatore di usare un determinato identificatore posto in un certo *namespace* è tramite lo ***scope resolution operator***, `operator::`. Questo operatore comunica al compilatore che ***l'identificatore posto alla sua destra si trova nel namespace posto alla sua sinistra***.

Modificando `main.cpp` in modo che venga richiamata la definizione di `doSomething()` posta all'interno del *namespace* `Bar`:
```cpp
#include <iostream>

int doSomething(int x, int y); // forward declaration

int main() {
	// Uso doSomething() del namespace Bar
	std::cout << Bar::doSomething(3, 4) << '\n';
	
	return 0;
}
```
Il risultato ottenuto è quello previsto, `-1`.
Se invece voglio utilizzare la definizione contenuta nel *namespace* `Foo`:
```cpp
#include <iostream>

int doSomething(int x, int y); // forward declaration

int main() {
	// Uso doSomething() del namespace Foo
	std::cout << Foo::doSomething(3, 4) << '\n';
	
	return 0;
}
```
Il risultato ottenuto è quello previsto, `7`
Questo operatore è **molto potente**, in quanto ci permette di ***selezionare arbitrariamente da quale namespace considerare un determinato identificatore***.
```cpp
#include <iostream>

int doSomething(int x, int y); // forward declaration

int main() {
	// Uso doSomething() del namespace Bar
	std::cout << Bar::doSomething(6, 0) << `\n`;
	// Uso doSomething() del namespace Foo
	std::cout << Foo::doSomething(3, 4) << '\n';
	return 0;
}
```
Questo codice stampa:
```
6
7
```

##### Usare `operator::` senza specificare un *namespace*
Se a sinistra di `operator::` non viene specificato un *namespace*, allora l'identificatore **verrà ricercato all'interno del *global namespace***.
```cpp
#include <iostream>

void print() { // funzione nel namespace globale 
	std::cout << " there\n";
}

namespace Foo {
	void print() // funzione nel namespace Foo
	{
		std::cout << "Hello";
	}
}

int main() {
	Foo::print(); // chiamata a print() del namespace Foo
	
	// In questo caso è uguale a scrivere print()
	::print();    // chiamata a print() del namespace globale.

	return 0;
}
```
In questo esempio, utilizzare `::print()` è uguale ad utilizzare `print()` senza `operator::`, che è di fatto superfluo. Tuttavia, questa notazione può essere utilizzata in contesti più utili.

#### Risoluzione di un identificatore all'interno di un namespace
Se viene usato un identificatore *all'interno di un namespace* **senza usare lo *scope resolution operator*** `operator::`, il compilatore **cercherà tale identificatore *nello stesso namespace***.
Se non viene trovato un identificatore valido, **esso viene cercato all'interno *degli altri namespace*, con il *global namespace* che viene controllato per ultimo**.
```cpp
#include <iostream>

void print() { // dichiarata nel global namespace
	std::cout << " bro!\n";
}

namespace Foo {
	void print() { // dichiarata nel namespace Foo
		std::cout << "Ciao";
	}

	void printHelloThere() {
		print();   // chiama print() contenuta in Foo
		::print(); // chiama print() contenuta nel global namespace
	}
}

int main() {
	Foo::printHelloThere();

	return 0;
}
```
Output:
```
Ciao bro!
```
- `Foo:printHelloThere()` viene chiamata. La prima chiamata di `print()` non fa uso di `operator::`, pertanto viene cercato un `print()` all'interno dello stesso namespace - esso esiste e quindi viene stampato `"Ciao"`;
- La seconda chiamata di `print()` fa uso di `operator::` senza però specificare un namespace. In questo caso **viene forzata la ricerca dell'identificatore nel *namespace globale***, che anche in questo caso esiste e quindi viene stampato `" bro\n"`.

#### Forward declaration di contenuti nei *namespace*
Nella lezione [[2.11 ~ Header Files|legata ai file header]] abbiamo visto come usare gli header per propagare le *forward declarations*. 
Per propagare gli identificatori che si trovano all'interno di namespaces, ***anche le forward declaration devono trovarsi all'interno dello stesso namespace***.
`add.h`
```cpp
#ifndef ADD_H
#define ADD_H

namespace BasicMath {
	int add(int x, int y); // Forward declaration, all'interno del namespace.
}

#endif
```
`add.cpp`
```cpp
#include "add.h"

namespace BasicMath {
	// Definizione di add() nel namespace.
	int add(int x, int y) {
		return x + y;
	}
}
```
`main.cpp`
```cpp
#include "add.h"
#include <iostream>

int main() {
    std::cout << BasicMath::add(4, 3) << '\n';
    return 0;
}
```
Se la *forward declaration* non si trovasse all'interno del *namespace* `BasicMath`, allora `add()` verrebbe ***dichiarata nel namespace globale*** - il compilatore a questo punto si lamenterà di non aver trovato una dichiaraizone per la chiamata `BasicMath::add()`.
Se invece *la definizione* non si trovasse all'interno del *namespace* `BasicMath`, allora sarà il linker a lamentarsi di non trovarsi una definizione per la chiamata `BasicMath::add()`.

#### Multipli blocchi `namespace` sono permessi
È possibile dichiarare ***dei namespace*** in **più blocchi diversi, quindi in posizioni diverse del codice**. Tutte le definizioni dello stesso namespace **sono considerate parte dello stesso namespace**.
`circle.h`
```cpp
#ifndef CIRCLE_H
#define CIRCLE_H

namespace BasicMath {
	// pi fa parte di BasicMath
	constexpr double pi { 3.141 };
}

#endif
```
`growth.h`
```cpp
#ifndef GROWTH_H
#define GROWTH_H

namespace BasicMath {
	// Anche e fa parte di BasicMath
	constexpr double e { 2.713 };
}

#endif
```
`main.cpp`
```cpp
#include "growth.h"
#include "circle.h"
#include <iostream>

int main() {
	std::cout << "Il valore di pigreco: " << BasicMath::pi;
	std::cout << "\nIl valore del numero e: " << BasicMath::e << '\n';

	return 0;
}
``` 
Output:
```
Il valore di pigreco: 3.141
Il valore del numero e: 2.713
```

Questa funzionalità permette di estendere anche il ***namespace delle funzioni della libreria standard***, il `namespace std`; tuttavia ***ciò non va fatto***, siccome tale namespace possiede una regola speciale che non gli permette di essere espanso.

#### Innestare namespace
È possibile innestare namespace all'interno di altri namespace.
```cpp
#include <iostream>

namespace Foo {
	namespace Bar {
		int add(int x, int y) {
			return x + y;
		}
	}
}

int main() {
	std::cout << Foo::Bar::add(3, 4) << '\n';
	return 0;
}
```
Output: `7`. 
Siccome `Bar` è innestato dentro `Foo` è possibile accedervi tramite `Foo::Bar`.
Da C++17 è possibile dichiarare i *nested namespaces* tramite questa forma:
```cpp
#include <iostream>

namespace Foo::Bar { // Uguale a innestare Bar dentro Foo
	int add(int x, int y) { // Funzione del namespace Foo::Bar
		std::cout << "Sono dentro Bar, innestato dentro Foo!\n";
		return x + y;
	}
}

namespace Foo {
	int add(int x, int y) { // Definita SOLO dentro Foo
		std::cout << "Sono dentro Foo!\n";
		return x + y;
	}
}

int main() {
	std::cout << Foo::add(3, 4);
	std::cout << Foo::Bar::add(3, 4) << '\n';
	return 0;
}
```
Output:
```
Sono dentro Foo!
7
Sono dentro Bar, innestato dentro Foo!
7
```

#### Alias per namespace
È possibile creare degli **alias** per i namespace, ossia un'identificatore alternativo che permette di accedere ad un particolare namespace. Per definire un alias, si usa la sintassi
```cpp
namespace Alias = NamespaceEsistente
```
Esempio:
```cpp
#include <iostream>

namespace Il::Mio::Bellissimo::Namespace {
	void stampaFraseBella() {
		std::cout << "Una bellissima frase!\n";
	}
}

int main() {
	// Creo un alias per Il::Mio::Bellissimo::Namespace
	namespace Semplice = Il::Mio::Bellissimo::Namespace;
	
	// Uso il namespace tramite l'alias
	Semplice::stampaFraseBella();
	
	return 0;
}
```
Output:
```
Una bellissima frase!
```

#### Come usare i namespace
Il meccanismo dei *namespace* è stato **principalmente inventato per evitare *naming collisions*** e non per implementare una gerarchia informativa - questo è evidente siccome tutto il namespace `std` racchiude **tutte le funzionalità della libreria standard**.
Per evitare collisioni, le nuove funzionalità della libreria standard vengono spesso innestate in namespace innestati ad `std`.

In generale, seguiamo queste linee guida per la definizione di namespace:
- Piccole applicazioni per uso personale non hanno **generalmente bisogno di namespace**. Se il progetto si sviluppa e diventa abbastanza grande, è opportuno creare namespace per evitare *naming collisions*.
- Qualsiasi codice che **viene condiviso con altri** ***deve*** essere inserito in appositi namespace, al fine di evitare collisioni con codice altrui - la maggior parte delle volte un singolo livello di namespacing (es. `FooLogger`) è abbastanza. Un altro vantaggio di questa pratica è che se inseriamo funzionalità di *libreria* all'interno del namespace, l'IDE di chi fa uso del nostro codice **autocompleterà** o offrirà **suggerimenti** su ciò che vi è contenuto (ad esempio, scrivere `FooLogger` mostrerà tutti gli identificatori presenti all'interno di `FooLogger`)
- In un progetto che coinvolge più persone, è opportuno usare anche **multipli livelli di innestazione dei *namespace***, al fine di evitare namespace su codice generato da altri.
	Questo può avvenire in tre forme:
	- Progetto//Libreria::Modulo: `FooLogger::Logging`;
	- Organizzazione::Progetto: `FooSoft::FooLogger';
	- Unione delle due sopra: `FooSoft::FooLogger::Logging`.
