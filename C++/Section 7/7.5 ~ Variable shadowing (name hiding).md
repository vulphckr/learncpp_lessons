Ogni [[7.1 ~ Compound statements (blocks)|blocco]] possiede la propria ***[[7.3 ~ Local Variables#Le variabili locali hanno *block scope*|block scope region]]*** - cosa succede se **una variabile contenuta in un blocco interno *possiede lo stesso nome* di una variabile contenuta in un blocco esterno?***

Quando succede **la variabile più interna *nasconde* quella più esterna*** nelle aree di codice in cui sono entrambe in *scope*. Questo fenomeno si chiama ***name hiding*** o ***variable shadowing***.

#### *Shadowing* di variabili locali
Prendiamo questo codice come esempio:
```cpp
#include <iostream>

int main { // Inizio blocco esterno
	int mele { 5 };
	{ // Inizio blocco interno
		// Viene stampato il valore esterno
		// Siccome non c'è conflitto tra scope
		std::cout << mele << '\n';
		
		int mele { 0 }; // Ora mele è definito nello scope del blocco interno
		
		// mele del blocco esterno è temporaneamente nascosto
		// da mele del blocco interno (variable shadowing).
		
		mele = 10; // cambio il valore di mele interno, non esterno!
		std::cout << mele << '\n'; // stampa 10
	} // mele del blocco interno va out of scope
	
	std::cout << mele << '\n'; // stampa 5, il valore di mele del blocco esterno
	
	return 0;
} // mele del blocco esterno va out of scope
```
Il programma stampa:
```
5
10
5
```
- Nel blocco esterno dichiariamo una variabile *locale* chiamata `mele`, con valore iniziale `5`. Ne viene stampato il valore, quindi stampiamo `5`
- Nel blocco interno dichiariamo una variabile *locale* chiamata `mele`, con valore iniziale `0`. Siccome questa ha lo stesso nome della variabile del blocco esterno, **da questo punto in poi l'identificatore `mele` farà riferimento alla variabile del blocco interno e non più quella del blocco esterno**. Assegnamo a questa variabile il valore `10` e poi stampiamo il valore, quindi stampiamo `10`.
- Alla chiusura del blocco interno, la variabile locale `mele` ***del blocco interno*** viene distrutta. **L'esistenza e il valore della variabile del blocco esterno *non subiscono variazioni***. Stampiamo il valore di `mele`, il quale è rimasto `5`, in quanto *esso non ha subito modifiche*.

Si nota anche che **se non avessimo dichiarato una variabile `mele` nel blocco interno**, allora ***l'identificatore continuerà a fare riferimento alla variabile del blocco esterno***:
```cpp
#include <iostream>

int main { // Inizio blocco esterno
	int mele { 5 };
	{ // Inizio blocco interno
		// Viene stampato il valore esterno
		// Siccome non c'è conflitto tra scope
		std::cout << mele << '\n';
		
		/* 
		   non dichiaro una variabile mele nel blocco interno
		   pertanto mele continuerà a fare riferimento 
		   alla variabile del blocco esterno
		*/
	
		
		mele = 10; // cambio il valore di mele esterno (!)
		std::cout << mele << '\n'; // stampa 10
	} // fine blocco interno
	
	std::cout << mele << '\n'; // stampa 10, il valore di mele del blocco esterno
	
	return 0;
} // mele del blocco esterno va out of scope
```
Output:
```
5
10
10
```

#### *Shadowing* di variabili globali
In modo simile, **in presenza di [[7.4 ~ Introduction to global variables|variabili globali]]**, se viene dichiarata una ***variabile locale*** che possiede lo stesso nome di una variabile globale, quest'ultima ***verrà nascosta nello scope (locale) della prima***.
```cpp
#include <iostream>

int value { 5 }; // Variabile globale

void foo() {
	// Qui non avviene shadowing - il valore viene effettivamente stampato
	std::cout << "Valore variabile globale: " << value << '\n';
}

int main() {
	int value { 7 }; // Questa variabile locale nasconde value globale
	
	++value;
	
	std::cout << "Valore variabile locale: " << value << '\n';
	foo();
	
	return 0; 
} // value (locale) va out of scope qui
// value (globale) va out of scope qui
```
Output:
```
Valore variabile locale: 8
Valore variabile globale: 5
```

Tuttavia, siccome le variabili globali ***fanno parte del namespace globale***, è possibile riferirsi a queste ***anche in caso di shadowing*** utilizzando `operator::` *[[7.2 ~ User-defined namespaces and the scope resolution operator#Usare `operator ` senza specificare un *namespace*|senza specificare un namespace]]*.

```cpp
#include <iostream>
int value { 5 }; // Variabile globale

int main() {
	int value { 7 }; // Variabile locale - fa shadowing a quella locale
	++value; // Incremento la variabile locale
	
	// Usando operator:: senza specificare namespace mi riferisco
	// esplicitamente alla variabile globale, la quale viene incrementata
	++(::value);
	
	std::cout << "Valore variabile locale: " << value << '\n';
	std::cout << "Valore variabile globale: " << ::value << '\n';
	
	return 0;
} // la variabile locale value va out of scope qui
// la variabile globale value va out of scope qui
```
Output:
```
Valore variabile locale: 8
Valore variabile globale: 6 
```

#### Evitare lo *shadowing*
Generalmente ***lo shadowing di variabili locali deve essere evitato***, siccome è molto semplice confondersi tra identificatori chiamati uguali ma usati in diversi scope.

Per lo stesso motivo è consigliabile anche ***non eseguire shadowing di variabili globali***, facilmente evitabile utilizzando il prefisso `g_` nell'identificatore di queste ultime.

È possibile attivare i warning per *variable shadowing* tramite la flag `-Wshadow` di GCC.
