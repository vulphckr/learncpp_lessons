In una [[2.5 ~ Introduction to local scope|lezione precedente]] abbiamo introdotto il concetto di ***variabile locale***, ossia una variabile che sono definite *solamente* all'interno di funzioni (di cui sono *variabili locali* anche i parametri).
C++ definisce le *variabili locali* in ***più modi***. In particolare le variabili locali possiedono diverse proprietà che *le differenziano* altre variabili **non locali**.

Inoltre, nella stessa lezione, abbiamo introdotto anche il concetto di ***scope***. Lo *scope* **di un identificatore** è lo spazio di codice ***in cui è possibile accedere a tale identificatore***. Quando una variabile è accessibile in un determinato momento si dice che essa è ***in scope***; se invece non può essere acceduta è ***out of scope***.
Essendo lo *scope* una proprietà ***compile-time***, se si prova ad accedere ad un identificatore quando esso è *out of scope* verrà generato un ***errore di compilazione***.

*Ricordiamo che le variabili vanno out of scope in ordine inverso a come sono state dichiarate, ossia dall'ultima dichiarata alla prima dichiarata.*
#### Le variabili locali hanno *block scope*
Le variabili locali hanno ***block scope***, ossia che **sono accessibili dal momento in cui vengono definite fino alla fine del [[7.1 ~ Compound statements (blocks)|blocco]] che le contiene**.
```cpp
int main() {
	int i { 5 }; // i è ora in scope
	double d { 4.0 }; // d è ora in scope
	
	return 0; 
} // fine del blocco: d e i vanno out of scope
```
Anche se i *parametri di funzione* non sono contenuti nel corpo della funzione (*che di fatto è un blocco*) anche essi **vanno *out of scope*** alla fine del blocco.
```cpp
int max(int x, int y) { // x e y entrano in scope
	int max { (x > y) ? x : y }; // max entra in scope
	
	return max;
} // max, y e x vanno out of scope
```

#### Tutti gli identificatori in uno *scope* devono essere univoci
I nomi delle variabili locali di un certo *scope* **devono essere univoci**, altrimenti qualsiasi referenza a tale identificatore potrebbe risultare ambigua. Se questa regola non viene rispettata, si avrà un ***errore di compilazione***.
```cpp
void myFunc(int x) { // x entra in scope
	int x {}; // Errore di compilazione: identificatore x già definito.
}

int main() {
	return 0;
}
```

#### Le variabili locali hanno *storage duration* automatica
Quando si parla di ***storage duration*** (o semplicemente ***duration***) di una variabile si intendono **l'insieme di regole che determinano come e quando una variabile viene istanziata e successivamente distrutta**. Nella maggoir parte dei casi, la *storage duration* coincide con il ***tempo di vita*** (***lifetime***) di una data variabile.

Le variabili locali hanno ***storage duration automatica***, questo significa che **vengono create nello stesso punto in cui vengono definite e vengono distrutte alla fine del blocco in cui sono contenute**. 
Per questo motivo le variabili locali sono anche dette **variabili automatiche**.
```cpp
int main() {
	int i { 5 }; // i viene definita E CREATA qui
	double d { 4.0 }; // d viene definita E CREATA qui
	
	return 0; 
} // fine del blocco: d e i vengono DISTRUTTE qui
```

#### Variabili locali e blocchi innestati
È possibile definire *variabili locali* all'interno di ***blocchi innestati*** - il comportamento di queste **non cambia**, ossia che rimangono in scope dal punto di definizione fino alla fine del blocco in cui si trovano.
```cpp
int main() {
	int x { 5 }; // x entra in scope
	
	{ // blocco innestato
		int y { 3 }; // y entra in scope
	} // y va out of scope
	
	// qua non posso usare y, siccome è out of scope
	
	return 0;
} // x va out of scope
```
Un qualsiasi blocco interno **si trova nello scope del blocco esterno ad esso**; questo significa che **le variabili definite nel blocco esterno *sono utilizzabili anche nel blocco interno***.
```cpp
#include <iostream>

int main {
	int x { 4 }; // x entra in scope 
	
	{ // blocco innestato, che fa parte del blocco esterno
		int y { 6 }; // y entra in scope
		
		// qui sia x che y sono in scope
		std::cout << x + y << '\n';
	} // y va out of scope
	
	// qui y non è in scope e non può essere usata
	return 0;
} // x va out of scope
```

#### Le variabili locali non hanno *linkage*
Altra proprietà degli identificatori è il ***linkage***. 
Il ***linkage*** di un identificatore determina *se le dichiarazioni dello stesso identificatore in altri scope diversi da quello in cui è stato definito* ***fanno riferimento allo stesso oggetto del primo***.

Le variabili locali ***non hanno linkage***: ogni dichiarazione di una variabile locale fa riferimento ogni volta ad un oggetto diverso.
```cpp
int main() {
	int x { 2 }; // variabile locale, non ha linkage
	
	{
		// non avendo linkage, questa x fa riferimento ad un oggetto diverso
		// dalla x fuori dal blocco
		int x { 3 }; 
	}
	
	return 0;
}
```
Questo caso specifico in cui la variabile del blocco interno ha lo stesso nome di quella del blocco esterno è un caso di *variable shadowing*, che vedremo in una prossima lezione.
#### Le variabili locali dovrebbero essere definite nello scope più limitato possibile
Se una variabile viene usata *solamente* all'interno di un blocco annidato, **essa andrebbe definita solo in quel blocco annidato**. 
Limitare lo scope di una variabile:
- ***riduce la complessità generale del programma***, riducendo il numero di variabili "attive".;
- permette di limitare l'uso di una variabile ad un determinato blocco, rendendola più facile da debuggare;
- rende più facile notare dove vengono usate determinate variabili.

È una ***best practice*** dichiarare le variabili ***nello scope quanto più limitato possibile al loro utilizzo*** - se una variabile è necessaria solo in un determinato blocco, essa va ***definita*** in quel determinato blocco.
