Abbiamo visto che possiamo aggiungere funzioni al nostro codice, che ci permettono [[2.6 ~ Why functions are useful, and how to use them effectively|una serie di comodità]]. Continuando ad aggiungere funzioni, il nostro programma diventa sempre più complesso e lungo - è pertanto opportuno ***separare il nostro programma in più files***.

[Guida per inserire i file su VSCode](https://www.learncpp.com/cpp-tutorial/programs-with-multiple-code-files/)

### Esempio multi-file
Consideriamo il programma (che non compilava) della [[2.7 ~ Forward declarations and definitions|lezione precedente]]:
```cpp
#include <iostream>

int main() {
	std::cout << "La somma tra 2 e 3 fa: " << add(2,3) << '.\n';
	return 0;
}

int add(int a, int b) {
	return a + b;
}
```
Il programma non compilava poiché, a riga 4, il compilatore non è riuscito a trovare l'identificatore `add` nel codice, poiché l'abbiamo definito solo dopo, a riga 9. Soluzione per questo problema era o **riordinare il codice** o usare una ***forward declaration***.

Supponiamo ora di avere il codice così separato in due file:
`add.cpp`:
```cpp
int add(int a, int b) {
	return a + b;
}
```
`main.cpp`:
```cpp
#include <iostream>

int main() {
	std::cout << "La somma tra 2 e 3 fa: " << add(2,3) << '.\n';
	return 0;
}
```

Il compilatore compilerà i file in un ordine non ben stabilito, ma ***uno alla volta***. Alla compilazione di `main.cpp` avremmo un ***errore di compilazione***, dovuto al fatto che non conosce l'identificatore `add` presente a riga 4.

Siccome compilati uno alla volta, anche se viene compilato `add.cpp` per primo, e pertanto il compilatore abbia trovato un identificatore `add`, quando viene compilato `main.cpp` il compilatore non si ricorda di tale identificatore. Questo viene fatto per una serie di ragioni:
- L'ordine di compilazione è invariante;
- Quando viene cambiato un sorgente, solo quel sorgente va ricompilato;
- Riduce possibilità di **conflitti di nome** tra identificatori in diversi file.

Anche qui le soluzioni sono due: mettere la definizione di `add` prima di `main` in `main.cpp`, oppure usare una ***forward declaration*** - in questo caso però la prima opzione non è applicabile, in quanto la funzione `add` è ***in un altro file***. Siamo pertanto costretti ad utilizzare una *forward declaration*:
`main.cpp`:
```cpp
#include <iostream>

int add(int a, int b); // Forward declaration

int main() {
	std::cout << "La somma tra 2 e 3 fa: " << add(2,3) << '.\n';
	return 0;
}
```
`add.cpp` rimarrà uguale.
In questo caso, quando verrà compilato `main.cpp`, il compilatore leggerà la ***dichiarazione*** di `add` e pertanto quando viene utilizzato l'identificatore lo considererà esistente - sarà il linker a collegare la funzione presente all'interno di `add.cpp` al corrispettivo identificatore dichiarato.
