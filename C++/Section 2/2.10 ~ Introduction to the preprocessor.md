## Il *preprocessor*
Alla compilazione di un programma ci si può aspettare che il compilatore legga il file (o i files) esattamente così come sono - tuttavia non è così. Infatti, prima della fase di compilazione il file passa per una fase chiamata di ***preprocessing***; qui, un programma, chiamato ***preprocessor*** effettua delle **modifiche locali al codice sorgente**. Queste modifiche sono locali poiché vengono realizzate per mezzo di file temporanei o avvengono temporaneamente in memoria.

Il preprocessore agisce principalmente su cose meno importanti, per esempio, scarta i commenti e si assicura che i file finiscano con un *newline*. Tuttavia ha una funzione molto importante: processare le ***direttive `#include`***.

Quando il preprocessore ha finito di tradurre un codice sorgente, il risultato viene chiamato ***translation unit*** ed è ciò che viene passato al compilatore per essere appunto compilato.

## Preprocessor directives
Il preprocessore agisce controllando il file dall'alto verso il basso e cercando delle particolari istruzioni, dette ***preprocessor directives***. Queste sono istruzioni che iniziano con il simbolo `#` e finiscono con un *newline* (**e non con un `;`**) e servono a segnalare al preprocessore di eseguire specifiche sostituzioni testuali all'interno del codice sorgente. Il preprocessore non conosce il C++, ma conosce semplicemente come certe sostituzioni testuali vanno eseguite, appunto, tramite le ***preprocessor directives***, che in alcuni casi possono sembrare simili al C++. Le *translation unit* **non possiedono direttive preprocessore**.

### `#include`
La direttiva preprocessore `#include` segnala al preprocessore di **sostituire tale direttiva con il contenuto del file che segue**. Anche i contenuti del file vengono preprocessati, generando anche inclusioni ricorsive.
```cpp
#include <iostream>

int main() {
	std::cout << "Hello world!" << '\n';
	return 0;
}
```
Quando il preprocessore, a riga 1, incontra la direttiva `#include <iostream>`, allora esso rimpiazzerà tale direttiva con il contenuto del file `iostream` - poi procederà a preprocessare i contenuti di `iostream` e poi il resto del file.

`#include` viene quasi sempre utilizzato per quanto riguarda l'inclusione di *header files*, che vedremo nella prossima lezione.

### Macro defines
La direttiva `#define` viene usata per creare una ***macro***. In C++, una ***macro*** è una regola che definisce come un determinato testo in input debba essere tradotto in output. 

Esistono due tipologie principali di macro: ***object-like*** e ***function-like***.

Le *function-like* agiscono in modo simile alle funzioni, ed hanno una funzione simile. L'uso di queste macro è ***sconsigliato*** perché ciò che si può fare con queste macro si può fare con le funzioni.

Le *object-like* possono essere definite in due modi:
```cpp
#define IDENTIFIER
#define IDENTIFIER sub_text
```
Il primo caso **non ha testo di sostituzione**, mentre il secondo lo ha. Siccome queste sono direttive preprocessore, e non *statement*, si noti come queste non terminino con `;`.

Le regole di nomenclatura per gli identificatori delle macro sono uguali a quelli degli identificatori standard in C++: possono essere usati lettere, numeri e underscore, ma non possono iniziare con questi ultimi due. 
È buona practice identificare le macro **per mezzo di nomi tutti maiuscoli separati da underscore**.

#### Object-like macros with substitution text
Quando il preprocessore incontra la direttiva `#define IDENTIFIER sub_text` viene fatta un'associazione tra l'identificatore specificato e `sub_text`. Da lì in poi, nel file, **ogni occorrenza dell'identificatore viene sostituita con `sub_text`**.
Un esempio è:
```cpp
#include <iostream>

#define CIAO "Ciao"

int main() {
	std::cout << CIAO << '\n';
	return 0;
}
```
Quando il preprocessore incontra `#define CIAO "Ciao"` viene associato all'identificatore `CIAO` il testo `"Ciao"`  (si noti come questo testo è precisamente `"Ciao"` con tanto di doppi apici `""`!). Da lì in poi, ogni volta che il preprocessore incontrerà `CIAO`, sostituirà `CIAO` con `"Ciao"`. La ***translation unit*** risultante sarà:
```cpp
// Contenuti di iostream

int main() {
	std::cout << "Ciao" << '\n';
	return 0;
}
```

Questa tipologia di macro veniva usata in C per **assegnare nomi a [[1.9 ~ Introduction to literals and operators#*Literals*|literals]]**. Questo però non è più necessario, poiché vedremo in futuro metodi migliori per fare questa cosa; l'uso di *object-like macros* con sostituzione di testo è pertanto ***scoraggiato***.

#### Object-like macros without substitution text
Le *object-like macros* possono essere specificate anche senza un testo da sostituire. Per esempio:
```
#define USE_YEN
```
Le macro di questo tipo funzionano esattamente come si potrebbe pensare: dopo che vengono incontrate l'identificatore specificato verrà sostituito l'identificatore ***con niente***.

A primo impatto queste macro potrebbero sembrare inutili - e lo sono se si devono effettuare sostituzioni di testo. Queste macro sono importanti per la **compilazione condizionale**, che vedremo a breve. 

L'uso di queste macro, al contrario di quelle con sostituzione di testo, non è scoraggiato.

### Conditional compilation
Le direttive preprocessore di ***conditional compilation*** vengono usate per specificare **sotto quali condizioni uno specifico blocco di codice debba essere o meno compilato**.
Esistono molteplici direttive di questo tipo, ma noi affronteremo solo `#ifdef`, `#ifndef` ed `#endif`.

La direttiva `#ifdef` permette al preprocessore di controllare se l'identificatore che la segue è stato definito in precedenza per mezzo di una direttiva `#define`. Se ciò risulta vero, il codice contenuto tra l'`#ifdef` e il successivo `#endif` viene considerato per la compilazione, altrimenti viene scartato.
Un esempio:
```cpp
#include <iostream>

#define COMPILA_QUI

int main() {
#ifdef COMPILA_QUI
	std::cout << "Stampa COMPILA_QUI" << '\n'; // Compilato
#endif

#ifdef COMPILA_ZIONE
	std::cout << "Stampa COMPILA_ZIONE" << '\n'; // Non compilato
#endif
	return 0;
}
```

In questo caso viene definito `COMPILA_QUI` tramite un `#define`. Quando viene incontrato `#ifdef COMPILA_QUI` il preprocessore controlla se `COMPILA_QUI` è stato definito - e siccome in questo caso è così, tutto ciò che è contenuto tra l'`#ifdef` ed `#endif` viene considerato nella compilazione. Quando però incontra `#ifdef COMPILA_ZIONE` il preprocessore controlla se `COMPILA_ZIONE` è stato definito - siccome in questo caso non è così, il codice tra l'`#ifdef` ed `#endif` viene scartato.

La direttiva `#ifndef` funziona in modo esattamente opposto a `#ifdef`: essa permette al preprocessore di controllare se l'identificatore che la segue **non** è stato definito, e in caso positivo considera il codice tra l'`#ifndef` e il successivo `#endif` per la compilazione, altrimenti viene scartato. Nell'esempio precedente, se al posto degli `#ifdef` avessimo avuto degli `#ifndef`, allora avremmo compilato il secondo blocco di codice e non il primo.

#### `#if 0`
Usare la direttiva `#if 0` permette di rendere blocchi di codice non disponibili per la compilazione, in modo simile a come se fossero all'interno di un commento. Questo è un metodo per escludere codice che contiene commenti multi linea.
```cpp
#include <iostream>

int main() {
	std::cout << "Marco" << '\n';
	
#if 0
	std::cout << "Luca" << '\n';
	std::cout << "Carlo" << '\n';
#endif
	return 0;
}
```
In questo caso verrà stampato solo `"Marco"`, poiché le altre due istruzioni sono escluse dall'essere compilate per mezzo della direttiva `#if 0`.

È possibile "*ri-abilitare*" del codice disabilitato per mezzo di `#if 0` semplicemente sostituendo `#if 0` con `#if 1`.
```cpp
#include <iostream>

int main() {
	std::cout << "Marco" << '\n';
	
#if 1
	std::cout << "Luca" << '\n';
	std::cout << "Carlo" << '\n';
#endif
	return 0;
}
```
Ora verranno stampati tutti e 3 i nomi: abbiamo *ri-abilitato* il blocco.

### Macro substitution with other preprocessor commands
Considerando il seguente codice:
```cpp
#include <iostream>

#define COMPILA_QUI

int main() {
#ifdef COMPILA_QUI
	std::cout << "Stampa COMPILA_QUI" << '\n'; // Compilato
#endif
	return 0;
}
```
Perché il preprocessore, una volta associato `COMPILA_QUI` al nulla, non sostituisce `COMPILA_QUI` nell'istruzione `#ifdef COMPILA_QUI` con nulla?

Nella maggior parte dei casi (***ma non sempre***, come nel caso di `#if` e `#elif`) il preprocessore esclude le *macro substitution* se avvengono all'interno di altre direttive preprocessore.

Un ulteriore esempio:
```cpp
#define CIAO 9 // Macro substitution

#ifdef CIAO // Non avviene la sostituzione - siamo in una direttiva preprocessore.
	std::cout << CIAO << '\n'; // Avviene la sostituzione - siamo in codice normale.
#endif
```

### The scope of `#define`s
Le direttive preprocessore vengono risolte ***prima della compilazione, dall'alto verso il basso***.
```cpp
#include <iostream>

void foo()
{
#define MY_NAME "Alex"
}

int main()
{
	std::cout << "My name is: " << MY_NAME << '\n';

	return 0;
}
```
In questo esempio, anche se il `#define` è all'interno del corpo di una funzione che non viene mai chiamata, la sostituzione di `MY_NAME` avverà. Questo perché il preprocessore ***non conosce i concetti di C++ come le funzioni, ma si limita a processare il testo e le direttive dall'alto verso il basso***. 

Anche nel caso di `#include` o usando [[2.7 ~ Forward declarations and definitions|una forward declaration]] le sostituzioni vengono fatte sempre ***in modo letterale dall'alto verso il basso***. È necessario pertanto assicurarsi che l'ordine con cui vengono fatte le sostituzioni sia corretto e lineare - pena un comportamento non ben specificato del programma.
