Come abbiamo visto [[2.7 ~ Forward declarations and definitions|nelle lezioni passate]] ogni identificatore deve possedere **un'unica definizione** nello scope in cui si trova. Un programma che definisce più identificatori restituirà un errore, o di compilazione o di linker (sulla base di quale [[2.7 ~ Forward declarations and definitions#One Definition Rule (ODR)|ODR]] viene violata).

Supponiamo di avere questi 3 file, di cui 2 header:
*NB: In questo esempio ci sono header contenenti definizioni di funzione. Questa non è una good practice, ma verrà utilizzata questa forma per far capire meglio l'esempio.*
`square.h`:
```cpp
int getSquareSides() {
	return 4;
}
```
`wave.h`:
```cpp
#include "square.h"
```
`main.cpp`
```cpp
#include "square.h"
#include "wave.h"

int main() {
	return 0;
}
```
Questo programma restituirà un errore di compilazione - questo poichè, a causa di un `#include` transitivo da parte di `wave.h`, `square.h` verrà incluso **due volte**. Quindi risulterà la seguente *translation unit*:
```cpp
int getSquareSides() { // da square.h
	return 4;
}

int getSquareSides() { // da wave.h che include transitivamente square.h
	return 4;
}

int main() {
	return 0;
}
```

### Header Guards
Al fine di evitare di includere più di una volte il contenuto di uno specifico header, è opportuno inserire all'interno dell'header stesso una ***header guard*** (chiamata anche ***include guard***). Le *header guard* hanno la seguente forma:
```cpp
#ifndef NOME_UNICO
#define NOME_UNICO

// Contenuto dell'header

#endif
```
Quando il preprocessore includerà l'header, controllerà prima di tutto se `NOME_UNICO` è stato definito per mezzo di una istruzione `#define` - se questo non è ancora avvenuto, allora definirà lui stesso `NOME_UNICO` e includerà i contenuti dell'header; tuttavia, se `NOME_UNICO` è stato già definito, i contenuti dell'header non saranno inclusi.

In questo modo, la prima volta che verrà incluso l'header, i contenuti verranno inclusi correttamente assieme alla definizione di `NOME_UNICO`; successivamente, se l'header viene nuovamente incluso, i contenuti non verranno copiati perchè `NOME_UNICO` è stato già definito.

Inserendo delle header guard nell'esempio precedente, si ottiene:
`square.h` 
```cpp
#ifndef SQUARE_DEFINE
#define SQUARE_DEFINE

int getSquareSides() {
	return 4;
}

#endif
```
`wave.h`:
```cpp
#ifndef WAVE_DEFINE
#define WAVE_DEFINE

#include "square.h"

#endif
```
`main.cpp`:
```cpp
#include "square.h"
#include "wave.h"

int main() {
	return 0;
}
```
Avremmo la seguente Translation Unit:
```cpp
#ifndef SQUARE_H // inclusione di square.h
#define SQUARE_H // SQUARE_H viene definito qui

// Questo viene incluso.
int getSquareSides()
{
    return 4;
}

#endif

#ifndef WAVE_H // inclusione di wave.h
#define WAVE_H
#ifndef SQUARE_H // SQUARE_H è già definito!
#define SQUARE_H // Questo codice non viene incluso.

int getSquareSides()
{
    return 4;
}

#endif
#endif

int main()
{
    return 0;
}
```
In questo modo `square.h` non verrà incluso due volte a causa dell'include transitivo. 

È bene ricordare che le header guard prevengono la doppia inclusione di un determinato header **all'interno di uno stesso file**. Questo può dar vita a problemi di inclusione che riguardano l'inclusione o l'uso di più file.

Il problema principale che risolvono le header guard, siccome ***non è good practice inserire definizioni negli header*** sta nell'evitare di includere più volte i contenuti dell'header stesso, che possono essere di varia natura (come per esempio tipi di dati creati dall'utente).

##### `#pragma once`
Un modo più semplice per realizzare le header guard è tramite la direttiva `#pragma once`. Al contrario degli header guard standard, dove è l'utente a proteggere l'header tramite `#ifndef`, `#define` e `#endif`, tramite `#pragma once` sarà direttamente il compilatore ad assicurarsi che i contenuti di un header non vengano inclusi due volte nello stesso file.

Alcuni compilatori permettono l'uso di questa direttiva, ma **non tutti**, tuttavia è una pratica generalmente accettata e anche molto usata.
