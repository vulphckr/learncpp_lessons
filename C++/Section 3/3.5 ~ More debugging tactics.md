Considerate le [[3.4 ~ Basic debugging tactics#Perchè stampare valori non è good practice|note negative]] che hanno le stampe ai fini di debug vediamo altri modi in cui è possibile effettuare debugging quando necessario.

#### Uso di condizionali per codice di debug
Uno dei problemi principali evidenziato per le stampe di debug è la loro eventuale **rimozione** una volta terminato il loro uso. È davvero necessario però rimuoverle?

Sarebbe comodo che tali stampe si attivassero se venisse attivata una "modalità di debug". Un modo facile per realizzarla è tramite [[2.10 ~ Introduction to the preprocessor#Conditional compilation|direttive condizionali del preprocessore]]. È possibile infatti definire una macro che "sblocca" le istruzioni di debug racchiuse tra direttive `#ifdef`, in modo da attivare il debug nel momento in cui è presente la macro.

```cpp
#include <iostream>

#define ABILITA_DEBUG // Macro per abilitare il debug - decommenta per attivare.

int getNumber() {
#ifdef ABILITA_DEBUG
std::cerr << "Chiamata getNumber()" << '\n';
#endif
	std::cout << "Inserisci un numero: ";
	int x{};
	std::cin >> x;
	return x;
}

int main() {
#ifdef ABILITA_DEBUG
std::cerr << "Chiamata main()" << '\n';
#endif
	int x{ getNumber() };
	std::cout << "Hai inserito: " << x << '\n';
	return 0;
}
```
In questo esempio, se decommentiamo `#define ABILITA_DEBUG`, allora le stampe di debug verranno attivate, altrimenti non verranno considerate in fase di compilazione.

Questa alternativa rende il codice più ingombrante, ma toglie i rischi di inserire e rimuovere codice. Seppur meglio della versione non condizionale, è possibile fare di meglio.

#### Uso di Logger
Un approccio alternativo per effettuare debugging è tramite l'uso di ***log***. 
Un ***log*** è una successione di eventi che si sono verificati in un dato contesto, solitamente ordinati in maniera temporale e ciascuno avente il momento esatto in cui è avvenuto.
L'azione di generare un *log* si chiama ***logging*** e viene effettuato da un'entità chiamata ***logger***.

Solitamente i log vengono scritti in file su disco, chiamati ***file di log***, così che possano essere analizzati in un secondo momento.

I file di log hanno un vantaggio a confronto di tutti i metodi di debug precedenti: spostano tutte le stampe di debug dall'output a un file separato - in questo modo l'unico problema che si verificava con le stampe condizionali viene colmato. Inoltre i file di log possono essere molteplici e facilmente condivisibili, rendendo la correzione possibile anche da più persone.

In C++ è possibile fare uso di molteplici logger. La libreria standard ha essa stessa un logger, `std::clog`, il quale però scrive sullo ***standard error stream***, pertanto non genera file. Esistono tuttavia logger che generano file, quali `plog` o `spdlog`.
